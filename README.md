# PORTIA OS

Интерактивная база вымышленных вирусов в виде рабочего стола научной станции.

Пошаговая инструкция по изменению и проверке сайта находится в [EDITING_GUIDE.md](EDITING_GUIDE.md).

## Как работает опубликованный сайт

- Посетители открывают сайт без регистрации и видят актуальную базу.
- Содержимое и профили сотрудников хранятся в Supabase и обновляются на сайте без изменения кода.
- Состав сотрудников раз в час подтягивается из Google-таблицы и Roblox; Netlify Blobs хранит только этот кэш и запасную копию содержимого на случай недоступности Supabase.
- У каждого редактора собственный аккаунт Supabase; владелец сам выдаёт и отзывает доступ по email.
- Если два редактора сохраняют одновременно, второй получит предупреждение вместо молчаливой перезаписи чужих правок.

## Первичная настройка Supabase

1. Создайте проект в Supabase.
2. В файле `supabase/portia_setup.sql` укажите email владельца в функции `portia_owner_email()` — это единственное место, где он задаётся.
3. Откройте **SQL Editor** и выполните этот файл. Его можно выполнять повторно после каждого обновления кода.
4. Откройте **Authentication → Sign In / Providers → Email** и обязательно включите **Confirm email**. Без подтверждения email любой, кто знает адрес будущего редактора, сможет зарегистрироваться раньше него и получить его права.
5. Там же рекомендуется включить **Leaked password protection**.
6. Откройте **Authentication → Users** и создайте пользователя с адресом владельца и надёжным паролем.
7. В **Project Settings → API** скопируйте URL проекта и Publishable key.

## Переменные окружения

Добавьте локально в `.env.local`, а затем в **Netlify → Project configuration → Environment variables**:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

Publishable key разрешено использовать в браузере. Service Role key этому сайту не нужен и не должен добавляться в публичные переменные.

## Публикация в Netlify

Сайт работает только на Netlify: ежечасные функции (`netlify/functions/`) и кэш Netlify Blobs на других хостингах недоступны.

Netlify подключён к GitHub-репозиторию и публикует ветку `main` автоматически:

1. Изменения вносятся в отдельной ветке и оформляются как Pull Request.
2. Netlify собирает для Pull Request предварительную версию со ссылкой — проверьте её.
3. После слияния Pull Request в `main` Netlify сам публикует сайт.

Предварительная версия работает с той же базой Supabase, что и основной сайт: изменения, сохранённые в ней через редактор, попадут на основной сайт.

## Как выдать доступ другому редактору

1. Войдите в сайт под главным аккаунтом владельца.
2. Откройте **Настройки → Открыть редактор → Доступ**.
3. Введите email человека и нажмите **Выдать доступ**.
4. Этот человек открывает `/owner-login`, вводит тот же email, придумывает собственный пароль и нажимает **Создать аккаунт**.
5. После подтверждения email он сможет войти в редактор.

Отозвать права можно в том же разделе **Доступ**. Главный аккаунт владельца удалить оттуда нельзя.

## Как менять содержимое без кода

1. Откройте опубликованный сайт.
2. Запустите **Настройки**.
3. Нажмите **Войти в редактор** и введите email и пароль Supabase.
4. Вернитесь в **Настройки** и нажмите **Открыть редактор**.
5. Измените нужный раздел и нажмите **Сохранить всё**.

Настройки фона, цвета и размера ярлыков сохраняются отдельно на каждом устройстве.
