Root causes (observed at planning time, line numbers on HEAD 12bcd0f):
- Pinned editor chrome: app/portia.css:521-525 (commit e677fae, Phase 14 UAT 38). Inside `@media (min-width: 901px)`, `.content-editor` stops scrolling and only the inner form/layout scrolls, so the header, tab strip and guidance line take up the top of the window permanently. That is the opposite of UAT 38's own expectation ("headings remain at their natural top position").
- Editor tabs not filling the window: `.flat-editor-form` max-width 900px (portia.css:781, used by «Информация», «Справочник», «Сводка»), `.compact-editor` 720px (782, «Рекомендации»), `.assistant-editor` min(100%, 1040px) (783, «Помощник»), `.access-editor` 760px (755, «Доступ»). «База вирусов», «Корзина» and «Сотрудники» use the `minmax(0,1fr)` grid of `.virus-editor-layout`, which already fills. That is why the owner's list names exactly the six capped tabs.
- «Сводка» cards stretch: `.broadcast-grid` (portia.css:437) is a single implicit full-width column, so every card is as wide as the window.
- «Справочник» tiles stretch: `.guide-grid` (portia.css:1718) uses `minmax(176px, 1fr)`, so tiles grow until another column fits.
- Six recommendations: components/portia-desktop.tsx:1290 renders `content.searchRecommendations` through a hard-coded first-six slice. The editor «Рекомендации» textarea (components/portia-editor.tsx:1311) accepts any number of lines. The editor has no numeric "maximum" field; the "squares" are the `.recommendation-order-row` rows, one per line.
