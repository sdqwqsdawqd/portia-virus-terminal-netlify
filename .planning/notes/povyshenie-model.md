# «Повышение»: как это работает

## Звания и ранги

4 ранга по 2 звания, всего 8 званий. В таблице «Кд» — кулдаун после звания.

| Ранг | Уровень | Звание | Заданий для повышения | Кд |
|------|---------|--------|-----------------------|----|
| Кадет / LRS — Кэнсюсэй | 1 | 1. Академик | — (стартовое) | — |
| | | 2. Стажёр | тест + документ | 3 дня |
| C rank / JMRS — Сэнкосэй | 2 | 3. Лаборант | 2 | 4 дня |
| | | 4. Исследователь | 3 | 6 дней |
| B rank / MRS — Тюсэй | 3 | 5. Ассистент | 4 | 8 дней |
| | | 6. Научный сотрудник | 5 | 10 дней |
| A rank / HRS — Дзёсэй | 4 | 7. Специалист вирусолог | 5 | 18 дней |
| | | 8. Эксперт вирусолог | задание аналитика | — |

На втором звании ранга (2, 4, 6) сотрудник упирается в «потолок». Пройти дальше можно только после **квалификационной проверки**: Кадет→C, C→B, B→A. Проверка даёт только **право** на повышение, а не само повышение.

Сами тексты заданий для сайта из документа не берутся: их составляет тот, у кого открыта вкладка «Повышение».

## Поток 1: повышение

1. Человек вписывает свой ник и отправляет запрос.
2. Если ника нет в A61:E85, запрос отменяется сразу и никуда не уходит.
3. Спамить запросами нельзя. Предложение: один активный запрос на ник, повторный запрос — только после закрытия предыдущего, плюс ограничение частоты по нику и IP.
4. Запрос видят те, у кого открыта вкладка «Повышение». Проверяющий сам спрашивает человека в стороннем мессенджере (Discord), выполнены ли условия.
5. Если ответ положительный, проверяющий одобряет и выдаёт задания:
   - **выбранные**: отмечает конкретные задания;
   - **случайные**: перед выдачей сайт показывает, какие именно задания выпали, и только после этого проверяющий подтверждает выдачу.
   - Число заданий берётся из звания (таблица выше).
6. Человек получает на сайте уведомление «Вам пришли задания» с подробностями. Откатить или поменять задания **нельзя**. Удалить, поменять или откатить их может только проверяющий.
7. Доказательства выполнения человек присылает в мессенджере, на сайт их не загружает.
8. Когда выполнены все задания, профессор нажимает на сайте «разрешить сдать / одобрить».
9. Следующие задания не выдаются, пока:
   - действует **анти-спидран**: столбец D в A61:E85 и дата в столбце E;
   - в таблице **не поменялось** звание (или звание и ранг) после прошлого повышения.

## Поток 2: квалификационная проверка

1. Запрос и проверка ника — как в потоке 1. Без ника в A61:E85 запрос не отправляется.
2. Проверяющий связывается с человеком. Оба заходят в звонок, человек включает демонстрацию экрана.
3. Проверяющий на сайте нажимает «одобрить сдачу», и сразу начинается тест.
4. Тест:
   - на каждый ответ одна минута, ходить можно только вперёд;
   - для каждого перехода (Кадет→C, C→B, B→A) свой набор: число вопросов, типы (варианты ответа, развёрнутый ответ и т. п.). Набор составляет тот, у кого открыта вкладка «Повышение»;
   - вопросы одинаковые для ПК и для телефона.
5. Защита от списывания — **только на ПК**:
   - на время теста рабочий стол убирается, остаётся одно окно теста, его нельзя свернуть;
   - если сайт заметил уход со вкладки, потерю фокуса или выход со страницы, тест сразу провален.
   - Полностью запретить сворачивание браузера нельзя. Сайт только замечает это и завершает тест.
   - На телефоне защиты нет, тест проходит обычно.
6. После сдачи все ответы уходят проверяющему. Он ставит каждому ответу только «верно» или «неверно» и отправляет результат.
7. Итог «прошёл / не прошёл» решает проверяющий в конце. Человек видит только итог и, максимум, процент. **В чём ошибся, не показывается.**
8. Если не прошёл — ожидание пересдачи. По умолчанию 2 дня, срок выбирает проверяющий. По документу это 1, 2 и 3 дня для трёх переходов. За замеченное списывание проверяющий может выбрать наказание больше, по документу — пересдача через 1,5 недели.
9. Устная и практическая части (показ в игре) остаются в звонке, сайт проводит только письменную часть.

## Права

- Отдельная вкладка редактора **«Повышение»**. Владелец доверяет её людям так же, как остальные вкладки: чипом в «Доступе».
- По умолчанию вкладка **закрыта** у всех, в отличие от 7 вкладок сайта, которые по умолчанию открыты (Phase 12 D-05). Как это заложено в хранении — Phase 12 D-24.
- Выдавать и отзывать доступ редакторам по-прежнему может только владелец.

## Кто что видит

- Результат («задания пришли», «прошёл / не прошёл», процент) показывается на сайте как уведомление по нику. Аккаунта у человека нет, поэтому результат увидит любой, кто введёт этот ник. Владелец согласен.
- Ответы на тест и историю видят только те, у кого открыта вкладка «Повышение».

## Хранение без мусора в Supabase (требование владельца)

- Хранить только живое: активные запросы, выданные и ещё не закрытые задания, идущий или непроверенный тест.
- После закрытия оставлять одну короткую строку на ник: последний итог, процент, дата, «пересдача не раньше…». Ответы теста и закрытые запросы удалять.
- Отменённые запросы (ника нет в таблице) не записывать вообще.
- Неподтверждённые и брошенные запросы чистить автоматически, например через N дней.
- Нагрузка — около десятка заявок в неделю.
