# Phase 03.3 Plan 03: Guide photo and YouTube video blocks Summary

**Guides in «Информация» now mix text, tables, uploaded photos and YouTube videos in any order: an editor pastes a YouTube link (only the 11-character id is kept), readers play it inline from youtube-nocookie.com and can open it on youtube.com; photos go through the same /api/uploads path as other site images.**

## Accomplishments

- `parseYoutubeId` (lib/portia-content-normalize.ts): `new URL` parse, http/https only, host allow-list (youtube.com, www., m., youtu.be, www.youtube-nocookie.com), id from `v` on /watch, first segment on youtu.be, or after /embed/ or /shorts/; result must match the id pattern shared with `normalizeInfoSections`. Tests cover accepted forms and look-alike hosts, scripts, encoded payloads, bad ids, non-strings.
- Editor: `YoutubeField` (typed text local, shown value derived at render so undo/redo works without an effect; status line «Видео распознано» / «Нужна ссылка на YouTube…»); «+ ФОТО» card with `ImageEditorField` (placement `guide`, `uploadImage`, writes `block.url` by ids inside `changeDraft`); block delete disabled for photo blocks while `uploadState === "uploading"`.
- Desktop: `figure.info-block-video` (lazy, titled iframe on the fixed nocookie origin, default referrer policy, «Открыть на YouTube ↗» with `rel="noopener noreferrer"`) and `figure.info-block-photo` (lazy `img`, alt «Иллюстрация: <подраздел>», trash image's `no-referrer`). Empty videoId / url renders nothing.
- CSS: 16:9 video frame, guide photo sizing with thin border, `.editor-image-preview.guide`. No colour literal.
