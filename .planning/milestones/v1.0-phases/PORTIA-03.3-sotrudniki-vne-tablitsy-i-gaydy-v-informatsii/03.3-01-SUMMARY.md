# Phase 03.3 Plan 01: Manual employees outside the sheet Summary

**Editors add a person outside the Google Sheet by Roblox nickname (typed Звание/Ранг/Позывной), the person is listed after the sheet staff with a «ВНЕ ТАБЛИЦЫ» mark, gets photo (link or upload), ratings and biography through the existing profile save, and can be removed; sheet employees cannot. The code works before the table exists.**

## Accomplishments

- `lib/portia-employees.ts`: `source` on `PortiaEmployee`; `sanitizeManualEmployee`, `isMissingTableError`, `readManualEmployees` (explicit columns, tolerant of a missing table), `mergeManualEmployees` (sheet wins on id or nickname, order continues after the sheet), `addManualEmployee` (nickname pattern, Roblox lookup, duplicate check, insert, 23505 and missing-table mapping), `removeManualEmployee` (sheet refused before any database call). `loadEmployees` reads manual rows in the same `Promise.all`, uses one Roblox call for sheet plus manual nicknames, marks the roster incomplete only on a real manual read error, and returns its `profiles` index.
- `app/api/employees/route.ts`: `POST` (404 «Ник не найден», 409 «Уже есть в списке», 503 Roblox, 503 pending database, 201 with `withProfile`) and `DELETE` (403 for a sheet employee, 404, `{ id }`), both behind `getEditorAccess().canEdit`. GET and PATCH untouched.
- `components/portia-editor.tsx`: «+ ВНЕ ТАБЛИЦЫ» add form with its own state (profile draft guard untouched), mark in the editor list, «УДАЛИТЬ СОТРУДНИКА» only for `source === "manual"` behind `ConfirmDialog`, photo field replaced by `ImageEditorField` with upload applied only to the employee it started for.
- `components/portia-desktop.tsx`: mark in the personnel list and profile identity; `updateEmployee` appends a new id; `removeEmployee` (+ cache rewrite) passed as `onEmployeeRemoved`.
- `app/portia.css`: `.manual-mark`, `.employee-add-form`, `.employee-add-error`, `.employee-remove` on existing tokens (no colour literal).
- `supabase/portia_setup.sql`: the plan's SQL block inserted byte-for-byte (diffed against the plan) between the profiles policies and `-- Media`; 41 additions, 0 deletions.
