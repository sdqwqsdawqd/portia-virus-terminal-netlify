## Pattern Assignments

### Manual employee storage (migration)

**Analog:** `supabase/portia_setup.sql`. Idempotent DDL and the RLS style to copy:
```sql
create table if not exists public.portia_employee_profiles (employee_id text primary key, ... updated_by uuid references auth.users(id));
alter table public.portia_employee_profiles add column if not exists nickname text not null default '' check (length(nickname) <= 64);
-- RLS (153-175)
drop policy if exists "Editors can create PORTIA employee profiles" on public.portia_employee_profiles;
create policy "Editors can create PORTIA employee profiles" on public.portia_employee_profiles for insert to authenticated with check ((select public.portia_can_edit()));
```
Recommendation (Claude's discretion): the least SQL is a new table `portia_manual_employees` (employee_id text pk `roblox-<id>`, nickname, title, rank, callsign, each with a length check, created_at, created_by). Give it select for anon and authenticated, insert/delete for authenticated, and the policy gated by `portia_can_edit()`. This needs a delete policy plus `grant delete`, which the profiles table lacks. Profiles stay keyed by `employeeId`, so nothing migrates. The owner must approve and run the SQL (see 03.2-06). Read it with `select("*")` and tolerate a missing table, the way `isMissingColumnError` tolerates missing columns, so the site does not break before the SQL runs.

### `lib/portia-employees.ts` (service)

**Roster merge.** In `loadEmployees` (249-270), `rosterFromRows` returns sheet staff and `withProfile(employee, index)` attaches the profile. Append the manual rows after the sheet roster, then dedupe by id so the sheet wins (D-03):
```ts
return {
  employees: rosterFromRows(rows, roblox.byName, index.robloxIdByNickname).map((employee) => withProfile(employee, index)),
  syncedAt: ..., complete: Boolean(profiles) && roblox.ok, profilesRead: Boolean(profiles),
};
```
Add `source: "sheet" | "manual"` to `RosterEmployee`. Use `order: sheetCount + i` for manual rows. Avatars for manual rows come from `resolveRobloxProfiles` over their nicknames, in the same call as the sheet nicknames.

**Add validation.** `resolveRobloxProfiles(usernames)` (131-166) is module-private, so export it or wrap it. It returns `{ byName, ok }`. An empty `byName` with `ok: true` means «Ник не найден». `ok: false` means Roblox is unreachable, so return 503 and not «Ник не найден». The key is `nicknameKey(name)`. The id is `employeeId(nickname, profile.id)`, giving `roblox-<id>`. If the id already exists in the sheet roster or the manual table, answer «Уже есть в списке» (409).

**Save pattern** (`saveEmployeeProfile`, 272-291): `supabase.from(table).upsert/insert(...)`, `if (error) throw error`, stamped with `updated_by: userId`.

**Sanitizing text fields:** copy `sanitizeEmployeeUpdate` (293-314), meaning typeof checks, `.slice(0, n)` and `cleanText`. The nickname is trimmed and limited to 64 characters. Title, rank and callsign are limited to roughly 64 characters each, matching the SQL checks.

### `lib/portia-content.ts` and `lib/portia-content-normalize.ts` (model, transform)

**Analog:** `normalizeBroadcasts` (83-94) and the helpers above it:
```ts
const dayPattern = /^\d{4}-\d{2}-\d{2}$/;
export function normalizeBroadcasts(value: unknown): Broadcast[] {
  if (!Array.isArray(value)) return [];
  return value.filter((item): item is Broadcast => Boolean(item) && typeof item === "object").map((item) => ({
    ...item, important: item.important === true, conditions: typeof item.conditions === "string" ? item.conditions.slice(0, 4000) : "",
  }));
}
function normalizeMediaUrl(value: unknown, fallback = "") {   // 73-77, reuse for photo blocks
  if (typeof value !== "string") return fallback;
  const url = value.trim().slice(0, 2048);
  return url.startsWith("https://") || url.startsWith("/") ? url : fallback;
}
```
- **Current gap:** line 176 does `infoSections: candidate.infoSections`, an unvalidated passthrough. Replace it with `normalizeInfoSections(candidate.infoSections)`. Old flat sections get `subsections: []` (D-12). Do not drop sections that have no `subsections`.
- **Type shape (suggested):** `InfoSection { id; title; body; subsections: InfoSubsection[] }`, `InfoSubsection { id; title; blocks: InfoBlock[] }`. `InfoBlock` is a discriminated union on `type`: `text {text}`, `photo {url}`, `video {videoId}`, `table {rows: {key, value}[]}`. Every block has an `id`.
- **Limits** (copy the slice style): cap subsections and blocks per section (about 50 and 100), table rows (about 100), and text length (`slice(0, 20_000)`). Accept only the known `type` values, and give a string `id` to anything that lacks one.
- **YouTube:** store only the 11-character id, parsed from `youtube.com/watch?v=`, `youtu.be/` and `youtube.com/embed/` with `/^[\w-]{11}$/`. Reject any other host, so nothing arbitrary reaches the iframe `src`. Render `https://www.youtube-nocookie.com/embed/<id>` with `loading="lazy"`, and put the link to `https://www.youtube.com/watch?v=<id>` with `target="_blank" rel="noopener noreferrer"` beside it (D-09).
- **Tests:** copy the style of `lib/portia-content-normalize.test.ts` line 39 («broadcasts saved before 03.2 normalize ...»). Cases: a flat legacy section survives, a bad block type is dropped, a non-YouTube URL is rejected, an unsafe photo URL is blanked.

## Shared Patterns

- **Editor gate:** `getEditorAccess(supabase, data.user)` and `access.canEdit`, 403 with «Нет доступа к редактору.» (`app/api/employees/route.ts` 31-33, `app/api/uploads/route.ts` 16-20). Apply to POST and DELETE.
- **Cache purge:** `await purgeCacheTag(employeesCacheTag)` after any roster-changing write, and `noStoreHeaders` on write responses.
- **Untrusted input:** `typeof` checks plus `.slice(n)` plus an allow-list, with URLs only `https://` or `/` (`normalizeMediaUrl`, `sanitizeEmployeeUpdate`).
- **Russian UI text** and the word «отдел», never «отряд».
- **Production SQL:** idempotent (`if not exists`, `drop policy if exists`), applied only by the owner.
- **Ids:** `makeId("info")` and `updateById` for client-side drafts.
