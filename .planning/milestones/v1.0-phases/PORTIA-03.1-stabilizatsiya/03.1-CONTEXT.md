<decisions>
## Implementation Decisions

### D-01 Format panel never covers saving (owner, screenshot)
- On desktop (and phone) the floating «Редактор оформления» panel sits over the editor's «Не сохранено» bar, so СОХРАНИТЬ
  can't be pressed. Fix so the save action is always reachable while the panel is open (panel above the bar, or the bar's
  actions stay visible/accessible). Phone behaviour from 03-06/03-07 (panel takes the keyboard's place, save bar hidden while
  the panel is open, ГОТОВО brings it back) stays unless it is the cause; desktop must not hide or cover the bar.

### D-02 Colour cycling bug (owner)
- Clicking a colour several times starts "перебирать цвета" (cycles through colours). Each click must set exactly the clicked
  colour; repeated clicks on the same colour are idempotent. Root-cause it (likely the swatch toggles/rotates or state race
  with the stored selection / panel re-mount keyed by selection).

### D-03 Windows don't deform when shrunk (owner)
- Resizing windows, especially «Сотрудники», squashes the layout ("всё становится плоским"). Give every app window a sensible
  minimum width/height so content stays readable; the personnel window must keep its list + profile layout usable (stack or
  scroll rather than squash). Keep maximize/minimize behaviour.

### D-04 Editor employee list scrolls inside its own area (owner)
- In the editor's «Сотрудники» tab the employee list stands as a tall column and spills out of its box; you have to scroll the
  whole window. The list must scroll within its own bounded area.

### D-05 Assistant phrases share one font (owner)
- All Vivian phrases (tips, idle, activity, and the "offended"/after-patience-runs-out phrases) use the same font and size as the
  regular tips. Owner likes the tips' font; the offended phrases must stop using a different font/size.

### D-06 OS boot animation once per browser session; correct order (owner's tester)
- The boot / access-level check animation plays on every load. Play it once per browser session (sessionStorage); later loads in
  the same session open the desktop directly.
- Fix the ordering bug: sometimes the spider appears before the web. The sequence must be deterministic.

### D-07 Wallpapers (owner + tester)
- «Анимации: Выключены»: wallpaper is static and fully drawn (no motion at all), while the UI and Vivian keep the soft transitions
  from dd26f5b. This reverses the wallpaper part of dd26f5b only.
- «Включены»:
  - DNA helix («Спирали ДНК») moves jerkily → make it smooth (no stutter: check keyframes/transform, GPU-friendly transform,
    no layout-affecting props, consistent loop without a jump).
  - Web («Паутина») draw-in looks like it "stretches" before animating → draw without the stretch.
  - Remove the travelling "лучи" (pulses/orbit along the threads) — owner finds them distracting.
  - «Гель»: owner says it is poorly made; make it tidier/calmer (exact meaning not specified — keep it subtle and smooth, ask the
    owner in UAT if unsure).
- Switching wallpapers should crossfade instead of an instant swap (external review #11, partly fixed).

### D-08 Virus dossier classification layout (owner)
- Order: «Общий уровень опасности» and «Угроза распространения» above «Способ распространения».
- Spread methods laid out 3 per row; the additional classifications (разум, вид, внешность, поведение) also 3 per row.
- In the spread item, the title sits a head higher than its icon — align icon and title.

### D-09 Still-open external review findings (triaged against 18b345a)
- #7 Avatar onError marks broken image as loaded (portia-desktop.tsx ~1252, LoadingMedia ~1655): show a fallback image instead
  of an empty/broken area.
- #8 A successful empty employees list from Google Sheets is ignored (portia-desktop.tsx ~381, cache ~413): apply a genuine empty
  list; still ignore degraded/error responses.
- #9 Editor access management (loadEditors/addEditor/removeEditor, portia-editor.tsx ~1726-1760) has no try/catch: handle network
  errors, never leave the UI stuck in loading/saving.
- #10 Window drag/resize updates shared state on every pointermove (portia-desktop.tsx ~1453 → ~808): throttle to animation frames
  (rAF) or move locally and commit at the end, so the desktop doesn't re-render per event.
- Already fixed, do not redo: #1, #2, #3, #5; #4 fixed (per-employee upsert; last-write-wins between two editors on the same
  employee accepted for now); #6 (employee draft dirty check) belongs to phase 03.2.

### D-10 Next.js security update
- Upgrade next from 16.3.4 to the patched release (reviewer cites 16.4.1; verify with npm audit --omit=dev) and matching
  eslint-config-next if pinned. Build, tests and lint must stay green.

### Claude's Discretion
- Exact minimum window sizes, crossfade duration, helix/gel animation details, fallback image choice.
- How D-01 is solved on desktop (move panel above the bar vs keep bar actions visible), as long as saving is always reachable.
