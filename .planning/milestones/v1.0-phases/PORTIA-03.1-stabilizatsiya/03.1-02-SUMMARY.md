# Phase 03.1 Plan 02: Desktop review fixes Summary

Three open review findings in the desktop shell (D-09) are closed. If the sheet has no staff rows, the personnel window now empties and says «В таблице пока нет сотрудников.». A failed or partial sync (502, `degraded: true`, or a missing array) still leaves the last roster on screen and in the cache. Dragging or resizing a window no longer re-renders the whole desktop on every mouse move: the element is moved directly and desktop state is set once on release. A dead avatar URL now shows the dimmed PORTIA logo, and a dead dossier image shows the «ВИЗУАЛЬНЫЙ МАТЕРИАЛ / ОЖИДАЕТ ЗАГРУЗКИ» placeholder.

## What changed

- **acceptsRoster** returns `Array.isArray(employees) && (employees.length > 0 || degraded === false)`. fetchEmployees checks it right after `if (!response.ok) return;`. An accepted empty list clears the selection (`payload.employees[0]?.id ?? ""`) and is cached. The mount-time cache branch now accepts any cached array, empty ones included. The profile pane shows «В таблице пока нет сотрудников.» when the list is empty and `employeesSyncedAt` is set. Otherwise it keeps «Данные сотрудников ещё не синхронизированы.».
- **dragGeometry** is the old inline clamp from moveDrag, unchanged: x is limited to `[0, max(0, W-160)]` and y to `[0, max(0, H-46)]`. AppWindow has a `liveGeometry` ref and a `paint()` helper. moveDrag and moveResize only paint. endDrag and endResize clear the operation and call `onGeometry` once with the last painted geometry. beginDrag and beginResize still call it once to switch the inline style into geometry mode. The maximized and phone guards are unchanged.
- **EmployeeImage** gets a `failed` state. On the first error it swaps to `/assets/portia-logo.png` and applies the fallback class. If the fallback also errors, it sets `loaded`, so the skeleton stops. The full-avatar call site now passes `fallbackClassName="personnel-fallback"`. **LoadingMedia** returns `<MediaBlock src="" …>` after an error.

## Known limitations

- EmployeeImage's `failed` state resets per employee, because the profile body is keyed by employee id. It does not reset per URL. If an editor fixes the photo URL of the employee currently on screen after it failed, the fallback stays until another employee is selected or the page reloads. This matches the plan, which relies on the key by employee id.
