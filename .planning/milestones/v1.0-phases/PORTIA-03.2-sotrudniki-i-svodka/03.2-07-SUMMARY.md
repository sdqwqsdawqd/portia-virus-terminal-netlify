# Phase 03.2 Plan 07: Quest toast and faster content sync Summary

Gap closure for G-03.2-2b and G-03.2-2c: a new quest now appears as a small non-modal corner toast right after publishing, and other open tabs pick it up within about 10 seconds.

## Accomplishments

- `QuestToast` (aside, role="status", no backdrop, no focus move, no trap) replaces the modal `QuestPopup`. Closes by «×», by Esc while focus is inside it, or by «ОТКРЫТЬ КВЕСТЫ» (opens «Сводка» on «Квесты»).
- The toast effect no longer returns early for the open editor or an already shown item; it depends on `content.broadcasts, contentReady, booting, today` and always sets the `questPopup` result (null included), so a quest published while the toast is open is counted in it and an unpublished or already read one hides it (closes review IN-03).
- `contentSyncMs = 10_000` poll runs only while the tab is visible; a `visibilitychange` listener refetches at once on return, removed in cleanup. Route, CDN and `content-sync` code untouched.
- Settings card «Содержимое сайта» now says «информацию, сводку».
- `.quest-toast` CSS: fixed top 106px / right 12px, z-index 965, full width under 900px, body and conditions line-clamped, motion only under `html[data-motion="full"]`.
- Test "a quest published during the visit is offered once and then never again" pins publish, second publish, dismissal, later publish and reload.
