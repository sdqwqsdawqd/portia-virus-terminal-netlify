# Phase 03.2 Plan 01: Six employee ratings Summary

Six editor-set ratings (Знания, Знание лап, Био, S, Актив, Общая) in the employee editor and profile card, working both before and after the database columns exist.

## Accomplishments

- `employeeRatings` in `lib/portia-employees.ts` is the only place the labels are written. Editor fields and the card both map over it, so renaming «Знание лап» is a one-line change.
- Reads use `select("*")` and `profileFromRow`; absent or junk rating values become null («—»). Saves upsert all provided ratings, and on PGRST204/42703 retry without the five new columns and return `ratingsSaved: false`. Other errors are still thrown.
- `sanitizeEmployeeUpdate`: new ratings clamp to 1-10, null or empty clears, a missing key or non-numeric value leaves the rating unchanged. Knowledge rule unchanged.
- PATCH answers `ratingsPending: true` and echoes only stored fields when the columns are missing; the editor shows a notice built from the table labels.
- Card: Звание and Ранг in a 2-column block, six ratings in `dl.personnel-ratings` (3 per row, 2 per row under `@container (max-width: 460px)`).
- `supabase/portia_setup.sql` gains the exact additive block (10 lines, 0 deleted). SQL recorded, not applied; no database was touched.
