# Phase 03.2 Plan 04: Quest dates and conditions Summary

Quests now carry a start date, an end date and plain-text conditions, set in the editor and shown in «Квесты» with an АКТИВЕН / СКОРО / ЗАВЕРШЁН state derived from the visitor's local date, active first and finished dimmed.

## What was built

- **Task 1 (tracer):** `Broadcast.startsAt`, `endsAt`, `conditions`. `normalizeBroadcasts` keeps a date only when it matches `^\d{4}-\d{2}-\d{2}$`, otherwise `""`; conditions are a string sliced to 4000 characters, otherwise `""` (old broadcasts get empty values). Editor: for quests only, «Дата начала», «Дата окончания» (`min` = start) and «Условия» (plain textarea), all wired through `updateById` by id; new messages carry the empty defaults. Reader: dates line and a «УСЛОВИЯ» block rendered as React text (`white-space: pre-line`, no HTML). `broadcastSignature` adds the three fields only when at least one is set, so old broadcasts keep their stored signature.
- **Task 2:** `lib/broadcasts.ts` gains `localDateKey`, `questState` (inclusive, empty side ignored), `formatQuestDay`; `broadcastFeed` takes a required `today` and sorts the quests tab by state rank (stable; tasks rank as active). Desktop: `today` state set from the clock tick, passed to every `broadcastFeed` call; quest cards get a `quest-badge` («АКТИВЕН», «СКОРО · с дд.мм», «ЗАВЕРШЁН») and class `state-{state}`; tasks show no badge. CSS uses existing tokens only; `.broadcast-card.state-finished` at opacity .6.
- The reader shows quest fields only for `type === "quest"`, so values kept in the editor after switching a message to news/task do not leak into the public card.
- `app/api/content/route.ts`, `lib/content-sync.ts`, `lib/editor-items.ts` unchanged (`git diff --quiet HEAD` checked).
