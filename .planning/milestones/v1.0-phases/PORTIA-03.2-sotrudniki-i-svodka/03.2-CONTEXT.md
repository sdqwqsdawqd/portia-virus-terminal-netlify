# Phase 03.2: Сотрудники и Сводка - Context

**Gathered:** 2026-10-18 (from the owner's chat messages and answers)
**Status:** Ready for planning

<domain>
## Phase Boundary

Two features on existing apps: (1) more employee ratings in the employee editor and profile card, plus no lost employee drafts;
(2) the «Сводка» (broadcasts) app split into «Новости» and «Квесты», important news emphasised, quests with dates and
conditions, and a one-time popup for a new active quest. Bug fixes from 03.1 are done; shared shortcut layout (phase 4) and
text formatting (phase 5) are out of scope.

</domain>

<decisions>
## Implementation Decisions

### D-01 Employee ratings (owner)
- Ratings set by editors on the site, stored on the site (Google Sheets never touches them): «Знания» (existing
  knowledgeRating), «Знание лап», «Био», «S», «Актив», «Общая».
- The label «Знание лап» is taken literally from the owner; keep labels in one place so they are trivial to rename (ask in UAT).
- Scale: same as the existing knowledge rating (integer 1-10), unless research shows a reason to differ (Claude's discretion).
  «Общая» is entered manually like the others.
- Shown in the employee profile card (PORTIA://PERSONNEL) next to «Звание / Ранг / Оценка знаний», laid out so 6 ratings read well
  on desktop and phone.
- Storage: new columns on public.portia_employee_profiles (lib/portia-employees.ts ProfileRow/upsert, supabase/portia_setup.sql).
  This is an additive change to the PRODUCTION Supabase database (add column if not exists ... default ..., check range). It must be
  a blocking human checkpoint before applying, with the exact SQL shown; the SQL is also recorded in supabase/portia_setup.sql.
  Reads must tolerate the columns being absent until the migration is applied (fallback to defaults) so deploy order can't break
  the site.

### D-02 No lost employee drafts (external review #6)
- Switching to another employee or another editor tab must not silently drop unsaved employee edits: track dirty state and
  confirm (save / discard / cancel) like the content editor's close dialog, or keep drafts per employee. Reuse existing dialog
  patterns (ConfirmAction / portia-dialog).

### D-03 «Сводка» redesign (owner chose: tabs + popup)
- Tabs «Новости» and «Квесты» (tasks «task» may group with quests or stay visible — Claude's discretion, keep all existing
  broadcast types readable).
- Important news are visibly emphasised (an «важно»/pinned flag set in the editor, shown as a larger/accented card).
- Quests get start date, end date and conditions («условия») fields in the editor; the reader shows them (active / upcoming /
  finished state derived from dates).
- A new active quest pops up once per visitor as a separate window/dialog (remember seen quest ids in localStorage, safe on
  storage errors); not on every load.
- Content lives in the shared content JSON (lib/portia-content.ts Broadcast type + normalizePortiaContent) — no DB migration.
  Old broadcasts without the new fields must still load (normalize defaults). Keep the 03-08 id-based edits and sync/revision
  gate intact.

### Claude's Discretion
- Rating scale details, layout of the 6 ratings, exact quest card design, how tasks are grouped, popup visuals (must respect
  «Анимации: Выключены» soft mode), date input widget (native date inputs are fine).

</decisions>
