# Requirements: PORTIA OS — v1.2 Повышение

**Defined:** 2026-10-27
**Core Value:** Участник открывает сайт и сразу находит нужную запись; редактор правит её без потерь и без путаницы — и всё это выглядит как цельная «PORTIA OS».

## v1.2 Requirements

### Допуск и запросы

- [ ] **PROM-01**: Участник может проверить состояние повышения, введя ник без регистрации.
- [ ] **PROM-02**: Система принимает запрос только для ника из `Portia!A61:E85`.
- [ ] **PROM-03**: Несуществующий ник отклоняется без записи в Supabase.
- [ ] **PROM-04**: Для одного ника одновременно существует не более одного активного запроса каждого вида.
- [ ] **PROM-05**: Повторные запросы ограничиваются по нику и IP.
- [ ] **PROM-06**: Перед необратимым действием система повторно проверяет актуальное звание в таблице.

### Обычное повышение

- [ ] **TASK-01**: Проверяющий ведёт отдельный банк заданий для каждого целевого звания.
- [ ] **TASK-02**: Проверяющий задаёт необходимое количество заданий отдельно для каждого звания.
- [ ] **TASK-03**: Проверяющий может выбрать задания вручную.
- [ ] **TASK-04**: Проверяющий может получить случайный набор и увидеть его до подтверждения.
- [ ] **TASK-05**: После подтверждения участник видит неизменяемый выданный набор.
- [ ] **TASK-06**: Изменить или удалить выданное задание может только проверяющий.
- [ ] **TASK-07**: После выполнения проверяющий вручную разрешает повышение.
- [ ] **TASK-08**: Новые задания нельзя выдать до смены звания в Google-таблице после прошлого повышения.

### Сроки повышения

- [ ] **COOL-01**: Первое повышение Академика доступно после 7 дней в отряде.
- [ ] **COOL-02**: Система применяет сроки 3/4/6/8/10/18 дней для последующих званий.
- [ ] **COOL-03**: Переход после Стажёра, Исследователя и Научного сотрудника дополнительно требует пройденной квалификации.
- [ ] **COOL-04**: Эксперт вирусолог достигается только через особое задание.
- [ ] **COOL-05**: Все сроки вычисляются сервером по данным столбцов D–E, а не по часам устройства.

### Квалификационная проверка

- [ ] **QUAL-01**: Для переходов Кадет→C, C→B и B→A существуют независимые банки тестов.
- [ ] **QUAL-02**: Для каждого перехода отдельно задаётся количество вопросов.
- [ ] **QUAL-03**: Вопрос может иметь один вариант ответа, несколько вариантов или свободный текст.
- [ ] **QUAL-04**: Проверяющий может собрать тест вручную или случайно из нужного банка.
- [ ] **QUAL-05**: Тест начинается только после разрешения проверяющего.
- [ ] **QUAL-06**: Участник получает по одному вопросу, имеет общий серверный лимит 15 минут на весь тест и движется только вперёд.
- [ ] **QUAL-07**: Перезагрузка не сбрасывает текущий вопрос или его серверный срок.
- [ ] **QUAL-08**: На ПК уход со вкладки, потеря фокуса или выход со страницы завершает попытку провалом.
- [ ] **QUAL-09**: На телефоне защита от ухода не применяется.
- [ ] **QUAL-10**: Публичный интерфейс никогда не получает правильные ответы или будущие вопросы.
- [ ] **QUAL-11**: Проверяющий отмечает каждый ответ как верный или неверный.
- [ ] **QUAL-12**: Проверяющий вручную определяет итог независимо от процента.
- [ ] **QUAL-13**: Участник видит только итог и при необходимости процент, но не конкретные ошибки.

### Пересдачи и уведомления

- [ ] **RETRY-01**: После провала новый запрос заблокирован до даты пересдачи.
- [ ] **RETRY-02**: Система предлагает срок 2 дня, а проверяющий может изменить его.
- [ ] **RETRY-03**: Проверяющий может увеличить срок за списывание.
- [ ] **RETRY-04**: Количество попыток не ограничено.
- [ ] **RETRY-05**: После окончания срока участник получает уведомление по образцу уведомления о квесте.

### Права и редактор

- [ ] **PERM-01**: «Повышение» является отдельной trusted-вкладкой, закрытой по умолчанию.
- [ ] **PERM-02**: Только владелец выдаёт и отзывает доступ к вкладке.
- [ ] **PERM-03**: Все проверяющие API отклоняют запрос пользователя без доступа к `promo`.
- [ ] **EDIT-01**: В редакторе отдельно представлены «Запросы», «Задания» и «Квалификационные проверки».
- [ ] **EDIT-02**: Новые запросы видны проверяющему при открытой вкладке без внешних уведомлений.
- [ ] **EDIT-03**: Рядом с данными, удаляемыми через три дня, отображается ненавязчивая подсказка.

### Хранение

- [ ] **DATA-01**: Google-таблица используется только для чтения и не изменяет приложение «Сотрудники».
- [ ] **DATA-02**: В Supabase хранятся только активные запросы, незакрытые задания и текущие либо непроверенные тесты.
- [ ] **DATA-03**: При закрытии подробные ответы удаляются, а краткий результат сохраняется транзакционно.
- [ ] **DATA-04**: Для одного ника хранится не более трёх последних попыток.
- [ ] **DATA-05**: Брошенные запросы и просроченные незавершённые задания очищаются через три дня.
- [ ] **DATA-06**: Публичный запрос по нику не раскрывает банки, ответы, заметки или личность проверяющего.

## Future Requirements

- Внешние уведомления проверяющим через Discord, email или push.
- Аналитика сложности вопросов и статистика прохождения.
- Общая система приложений и унификация всех очередей рабочего стола.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Запись в Google Sheets | Таблица остаётся внешним источником текущего звания и меняется вручную |
| Загрузка доказательств на сайт | Доказательства передаются во внешнем мессенджере |
| Автоматический проходной процент | Итог всегда определяет проверяющий |
| Показ конкретных ошибок участнику | Защита банка вопросов; показывается только итог и опциональный процент |
| Полная защита от сворачивания браузера | Веб-сайт может только обнаруживать потерю видимости/фокуса |
| Неограниченная история | Для уменьшения мусора хранятся только три последних кратких результата |
