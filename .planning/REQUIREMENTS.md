# Requirements: PORTIA OS — v1.4 «Доступ и единый стиль»

**Defined:** 2026-11-09
**Core Value:** Сделать существующий PORTIA OS доказуемо устойчивым, безопасным и визуально последовательным, сохранив его текущую художественную основу.
**Milestone goal:** Закрыть сайт от посторонних входом по нику с заявкой и уровнями допуска и привести весь сайт к одному удобному стилю.

Решения владельца 2026-11-09 (D-71): закрытая запись показывается строкой «ЗАСЕКРЕЧЕНО · нужен допуск N» без названия (1б); «Устав» и «Таблица» скрываются только на сайте, прямые ссылки остаются открытыми и это записывается честно (2а); у хранилища картинок убирается получение списка, картинка открывается только по точной ссылке (3а); примеры МОРОК/АРАХНА — настоящая информация и убираются из кода страницы (4б); уровни выдаёт любой редактор, не выше своего и не себе, владельца изменить нельзя, всё в журнал (5а); уровни 3–5 называются «Уровень 3/4/5» (6а); в день включения владелец одобряет всех из таблицы одной кнопкой с уровнем 2 (7а); дизайн — три направления A/B/C на выбор, не больше одной переделки на экран (8а).

## v1.4 Requirements

### Вход по нику (ACC)

- [ ] **ACC-01**: Посетитель на загрузочном экране вводит ник Roblox и выбирает «из таблицы» или «не из таблицы» и отправляет заявку.
- [ ] **ACC-02**: Пока заявка не одобрена, посетитель не видит никакого содержимого сайта: ни приложений, ни данных, ни рабочего стола; только нейтральный экран «заявка на рассмотрении» / «отклонена» / «доступ отозван».
- [ ] **ACC-03**: Посетитель после одобрения при повторном открытии сайта на том же устройстве попадает сразу на рабочий стол, без повторного ввода ника.
- [ ] **ACC-04**: Ник принимается только в формате Roblox (латиница, цифры, `_`, 3–20 символов); регистр не создаёт второго человека.
- [ ] **ACC-05**: Ответы экрана входа не раскрывают, одобрен ли уже такой ник у кого-то другого; повторные заявки ограничены паузой и лимитом попыток.
- [ ] **ACC-06**: Отклонённый или отозванный посетитель может подать новую заявку после паузы.
- [ ] **ACC-07**: Заявка с нового устройства для уже одобренного ника создаётся как новая заявка на рассмотрение, а не одобряется автоматически.
- [ ] **ACC-08**: Редактор и владелец входят на сайт через существующий вход редактора, минуя заявку по нику; ссылка на вход редактора доступна с экрана заявки.
- [ ] **ACC-09**: Закрытие сайта включает и выключает только владелец; пока оно выключено, заявки уже собираются, а сайт работает как раньше.

### Вкладка «Пользователи» (USR)

- [x] **USR-01**: Любой редактор видит во вкладке «Пользователи» всех людей и заявки, по умолчанию сначала ожидающие, и счётчик ожидающих на вкладке.
- [ ] **USR-02**: Редактор видит у заявки ник, ссылку на профиль Roblox, выбранный тип и отметку, есть ли ник в таблице сотрудников (проверяется в момент решения).
- [x] **USR-03**: Редактор одобряет заявку; уровень заранее выставлен: «из таблицы» — 2, «не из таблицы» — 1.
- [x] **USR-04**: Редактор отклоняет заявку, меняет уровень человека и отзывает доступ.
- [ ] **USR-05**: Редактор не может одобрить себя, выдать уровень выше своего и изменить владельца; это проверяет база, а не только интерфейс.
- [ ] **USR-06**: Каждое решение записывается в журнал (кто, когда, что); у строки видно, кто и когда решил.
- [x] **USR-07**: Одновременные решения двух редакторов по одной заявке не ломают состояние: второй видит «уже решено».
- [ ] **USR-08**: Владелец одной кнопкой одобряет все ожидающие заявки «из таблицы», ники которых есть в таблице, с уровнем 2.
- [x] **USR-09**: Владелец может закрыть вкладку «Пользователи» отдельному редактору существующими правами вкладок.

### Уровни допуска (LVL)

- [ ] **LVL-01**: У каждого человека есть уровень 1–5 (названия «Уровень 1…5»); у редакторов и владельца — 5.
- [ ] **LVL-02**: Редактор задаёт нужный уровень каждой записи в «Базе вирусов», «Справочнике» и «Информации» и приложению «Устав»; запись без уровня — уровень 1.
- [ ] **LVL-03**: Вложенная часть не может быть доступнее родителя (раздел ≥ уровня приложения, подраздел ≥ раздела).
- [ ] **LVL-04**: Посетитель с недостаточным уровнем видит на месте записи только строку «ЗАСЕКРЕЧЕНО · нужен допуск N» без названия, картинки и текста.
- [ ] **LVL-05**: Закрытые записи не попадают посетителю ни в ответ сервера, ни в поиск, ни в рекомендации, ни в «Корзину», ни в кэш браузера.
- [ ] **LVL-06**: Записи учёных в карточке вируса необязательны: карточку можно сохранить без них, пустой блок не показывается, существующие записи не удаляются.
- [ ] **LVL-07**: Старые уровни записей учёных (II/III/IV) работают на той же шкале 1–5 по реальному уровню посетителя.
- [ ] **LVL-08**: Сохранение редактором никогда не удаляет записи, скрытые от других уровней (редактор всегда работает с полным содержимым).
- [ ] **LVL-09**: Изменение уровня или отзыв доступа применяется у посетителя при следующем обновлении данных без перезагрузки страницы.

### Повышение (PROM)

- [ ] **PROM-01**: Одобренный сотрудник «из таблицы» не вводит ник в «Повышении»: ник берётся из одобренной заявки на сервере, ник из браузера игнорируется.
- [ ] **PROM-02**: Существующие привязки устройств «Повышения» продолжают работать; конфликт ника решается существующим сбросом проверяющим.
- [ ] **PROM-03**: Набор регрессий «Повышения» из todo 2026-10-28 воспроизведён на текущем коде и каждый ещё живой пункт исправлен: дата без двойной точки; доступные заявки (обычная и квалификационная) отправляются и сразу видны в состоянии, недоступность показывает конкретную причину; ник восстанавливается на устройстве.
- [ ] **PROM-04**: Редактор заданий и квалификации надёжно выбирает количество заданий, добавляет, изменяет и удаляет задания и вопросы и показывает ошибки без потери введённого.
- [ ] **PROM-05**: В конструкторе шаблона есть окно «Видимая часть» для картинки; рамка повторяет место фото в карточке, как в «Базе вирусов».

### Защита данных (SEC)

- [ ] **SEC-01**: Аноним не может прочитать контент и список сотрудников напрямую из Supabase по публичному ключу; посетители читают их только через сервер с проверкой заявки.
- [ ] **SEC-02**: Ответы с закрытым содержимым не кэшируются на CDN Netlify; старые открытые копии сбрасываются при включении закрытия.
- [ ] **SEC-03**: Код и HTML страницы не содержат контента сайта (включая МОРОК и АРАХНА); проверка сборки ищет в собранных файлах маркеры контента.
- [ ] **SEC-04**: Кэш браузера с контентом очищается при любом переходе в неодобренное состояние и не показывает данные до одобрения.
- [ ] **SEC-05**: У хранилища картинок нельзя получить список файлов; картинка открывается только по точной ссылке.
- [ ] **SEC-06**: `portia_promo_register_attempt` больше не вызывается анонимом и обычным пользователем напрямую.
- [ ] **SEC-07**: Ограничение «Устава» и «Таблицы» действует только на сайте; это записано в известных ограничениях, требования не заявляют закрытие прямых ссылок.
- [ ] **SEC-08**: `next` и `eslint-config-next` обновлены до 16.4.5 (исправления безопасности Netlify 2026-11-03).

### Единый стиль (UI)

- [ ] **UI-01**: Владельцу показаны текстом три направления стиля (A строгий острый, B мягкий «оконный», C смешанный по смыслу) с таблицей значений; выбран один.
- [ ] **UI-02**: На всём сайте действует одно правило углов: где скругление, где острый угол; значения заданы общими токенами, а тест не даёт добавить произвольный радиус.
- [ ] **UI-03**: Кнопки, плашки, поля и вкладки выглядят одинаково на рабочем столе, в приложениях и во всех вкладках редактора.
- [ ] **UI-04**: Все вкладки редактора (включая поздние «Справочник», «Повышение», «Пользователи») используют одну раскладку и одинаковые элементы управления.
- [ ] **UI-05**: Крестик закрытия стоит в самом углу окна.
- [ ] **UI-06**: Развёрнутое на весь экран окно использует площадь без растянутых кнопок и пустых полос.
- [ ] **UI-07**: Иконки классификации перерисованы заново, кроме «Способа распространения», после согласования вариантов с владельцем.
- [ ] **UI-08**: «Информация» на телефоне показывает компактную кнопку разделов вместо ленты карточек; кнопка не перекрывает текст, список доступен с клавиатуры, подсветка поиска работает.
- [ ] **UI-09**: Ярлыки на ширине 521–900px расставлены одним правилом с JS (без недвижимых абсолютных ярлыков и блокировки прокрутки).
- [ ] **UI-10**: Известные находки axe исправлены (контраст `.eyebrow`, подсказок полей, `small[title]`, имя `.nested-editor-toggle`) и контраст проверен на всех акцентах.
- [ ] **UI-11**: Регрессии рабочего стола из todo 2026-10-28 проверены на текущем коде и живые исправлены: окна одинаково ограничены слева и справа; ярлыки не меняют резкость, масштаб и положение в конце анимации.

### Приёмка (UAT)

- [ ] **UAT-01**: Владелец проходит короткую проверку на PC и телефоне: вход по нику, вкладка «Пользователи», уровни, новый стиль. Непроверенное записывается как BLOCKED или принятый риск, не PASS.
