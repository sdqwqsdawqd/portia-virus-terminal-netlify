# Requirements: PORTIA OS — v1.1 Закрытие замечаний

**Defined:** 2026-10-19
**Core Value:** Участник открывает сайт и сразу находит нужную запись; редактор правит её без потерь и без путаницы — и всё это выглядит как цельная «PORTIA OS».

Источник: открытые замечания ревью v1.0 (`.planning/milestones/v1.0-phases/*/…-REVIEW.md`), сверены с кодом в `.planning/research/FEATURES.md`. В скобках — закрываемые замечания.

## v1.1 Requirements

### Учёт замечаний

- [ ] **TRIAGE-01**: Уже исправленные и устаревшие замечания закрыты с доказательством в записях ревью, без кода (01-CR-01, 05-IN-01, 05-IN-02, 05-IN-04, 05-IN-05, 03.2-IN-02, 03.2-IN-03 частично, старый 03.2 WR-03 `markQuestsSeen`)
- [ ] **TRIAGE-02**: Принятые риски и ограничения записаны в записях ревью и PROJECT.md: 01-WR-01 (Ctrl+колесо над чужим документом — ограничение браузера, есть кнопки +/−), 03.1-IN-10 (права на столбцы, почта владельца, анонимная проверка одобрения), 05-WR-05 (дубли matchMedia)
- [ ] **TRIAGE-03**: Перед правками сохранений владелец выгрузил `portia_employee_profiles` и `portia_content`; пункт STATE о переносе проекта закрыт (проект в `C:\Users\User\code\portia-site`)

### Сотрудники: сохранение без потерь

- [ ] **EMP-01**: Сохранение сотрудника меняет только присланные поля: отсутствующее поле не меняется, пустая оценка очищает только оценку, неверный тип даёт 400; старый формат запроса принимается (03.1-WR-02, 03.2-WR-04, 03.3-IN-02)
- [ ] **EMP-02**: Редактор отправляет только изменённые поля и сохраняет только при полностью прочитанном списке (`profilesRead === true`) — кэшированный или неполный список не стирает оценки (03.2-WR-02)
- [ ] **EMP-03**: Сохранение профиля не зависит от Roblox и Google-таблицы: действующий сотрудник находится по таблице/базе, нет 404 и ожидания ~18 с (03.1-WR-03)
- [ ] **EMP-04**: Сохранение деталей сотрудника вне таблицы не оставляет полузаписанного состояния и показывает верную причину ошибки (03.3-WR-03)
- [ ] **EMP-05**: Текст, набранный во время сохранения, не теряется; ответ сервера не перезаписывает черновик другого сотрудника; таймер «СОХРАНЕНО» сбрасывается (03.2-WR-03, 03.1-WR-06)
- [ ] **EMP-06**: При сбое чтения профилей или сотрудников вне таблицы посетитель видит последние хорошие данные, а кэш устройства не перезаписывается неполными (03.1-WR-01, 03.3-WR-02)
- [ ] **EMP-07**: Исправленная ссылка на фото сотрудника показывается сразу, без перезагрузки (03.1-WR-05)
- [ ] **EMP-08**: Кнопка «+ ВНЕ ТАБЛИЦЫ» доступна и при пустом списке сотрудников (03.3-WR-04)
- [ ] **EMP-09**: Ник сотрудника вне таблицы хранится в написании Roblox; запрет удаления сотрудника из таблицы определяется кодом ответа, а не русской строкой (03.3-IN-01, 03.3-IN-04 часть 2)
- [ ] **EMP-10**: 35-й и последующие сотрудники таблицы не пропадают молча — лимит виден или поднят (03.1-IN-03)

### Синхронизация и целостность контента

- [ ] **SYNC-01**: Опрос контента раз в 10 с не трогает редактор и рабочий стол, если ревизия не изменилась — история отмены сохраняется (03.1-WR-04, 03.2-WR-01)
- [ ] **CONT-01**: Сохранение никогда молча не обрезает текст, гайды и таблицы: лимиты подняты и общие для редактора и сервера, у лимита кнопка «+» неактивна с подписью, сервер не отклоняет и не урезает существующие документы (03.1-WR-07 обрезка, 03.3-WR-01)
- [ ] **CONT-02**: Новости, квесты и вирусы с полями неверного типа приводятся к правильному виду при сохранении и чтении, ничего не удаляя; `title: {}` не роняет сайт (03.1-WR-07 форма)
- [ ] **CONT-03**: Окончательное удаление вируса или файла из Корзины удаляет и их форматирование; восстановление сохраняет форматирование (03.1-WR-08)
- [ ] **CONT-04**: Новость, ставшая квестом, теряет «ВАЖНО»; квест никогда не показывает «ВАЖНО» (03.1-WR-09)
- [ ] **CONT-05**: Отмена/повтор смены типа новость↔квест переключает вкладку «Сводки» на эту карточку (03.2-IN-04)
- [ ] **CONT-06**: Квест с окончанием раньше начала исправляется или подсвечивается в редакторе, а не молча неактивен (03.1-IN-08)
- [ ] **CONT-07**: С первой отрисовки квесты с датами показывают верный статус (03.2-IN-05)
- [ ] **CONT-08**: Старый кэш контента без `recycledViruses` не роняет сравнение досье (03.1-WR-12)
- [ ] **CONT-09**: Путь `//host/x.png` не считается локальным ни в коде, ни в SQL-проверке (03.1-IN-02)

### Устойчивость

- [ ] **ROB-01**: Помощник с пустым или исчезнувшим советом не роняет рабочий стол; `FormattedText` переносит отсутствующий текст (03.1-WR-10)
- [ ] **ROB-02**: Неверный или пустой JSON в API сотрудников, редакторов и контента даёт 400 с понятным текстом, а не 500 (03.1-IN-06, 03.3-IN-03, плюс `PUT /api/content`, `POST /api/editors`)
- [ ] **ROB-03**: Побочные эффекты (localStorage, `setWindows`) вынесены из функций обновления состояния React (03.1-IN-09)

### Безопасность

- [ ] **SEC-01**: Приложение пускает в редактор только пользователя с подтверждённой почтой (`email_confirmed_at`) — проверка в коде, работает до применения SQL (03.1-WR-11 код)
- [ ] **SEC-02**: SQL требует подтверждённую почту в `portia_is_owner`/`portia_can_edit`; блок с предварительной проверкой `auth.users`, откатом и `begin/commit`; владелец проверил «Confirm email» в Supabase и применил SQL сам (03.1-WR-11 SQL)
- [ ] **SEC-03**: Встроенные «Таблица», «Устав» и YouTube работают в `sandbox` с общим набором разрешений; проверено в браузере (03.1-IN-07, 03.3-IN-04 часть 1)

### Права редакторов (новое)

- [ ] **PERM-01**: Владелец выдаёт доступ по email и для каждого редактора включает/выключает вкладки: База вирусов, Информация, Сводка, Корзина, Рекомендации, Помощник, Сотрудники
- [ ] **PERM-02**: Новый и уже одобренный редактор по умолчанию имеет все вкладки; владелец может забрать любые
- [ ] **PERM-03**: Редактор не видит закрытые для него вкладки
- [ ] **PERM-04**: Сервер отклоняет правки закрытых разделов (контент и сотрудники), даже если запрос отправлен в обход интерфейса; SQL для прав применяет владелец

### «Устав»/«Таблица»: масштаб

- [ ] **ZOOM-01**: Масштаб реагирует только на Ctrl (не на Win/Cmd), оверлей масштаба не залипает и не перехватывает клики (01-WR-02, 01-WR-03)
- [ ] **ZOOM-02**: Кнопка сброса масштаба озвучивает текущий процент (01-IN-03)

### Редактор и панель оформления

- [ ] **EDIT-01**: На телефоне ГОТОВО без известного выделения не ставит курсор в начало — следующее ✎ не цепляет первое слово (05-WR-01)
- [ ] **EDIT-02**: Бирюзовая метка цели заметна на светлом поле предпросмотра (контраст ≥ 3:1), проверено на ПК и телефоне (05-WR-06)

### Доступность и тексты

- [ ] **A11Y-01**: Уведомление о квесте закрывается Escape без фокуса, имеет верные роли; список с ролями option (03.1-IN-04, 03.2-IN-01)
- [ ] **A11Y-02**: Портрет Roblox и ручка ≡ имеют всплывающие подсказки (01-IN-01, 01-IN-02)
- [ ] **A11Y-03**: В редакторе нет шуточных и пустых надписей (03.1-IN-05)

### Тесты и порядок в коде

- [ ] **TEST-01**: Ключ настроек — одна константа, тест запуска ловит расхождение (03.1-IN-01)
- [ ] **TEST-02**: Тест на правило `::highlight` без заливки и граничный тест окна своего ввода; импорты `rich-text-style` объединены (05-IN-06, 05-IN-01, 05-IN-03)
