# Requirements: PORTIA OS — v1.1 Закрытие замечаний

**Defined:** 2026-10-19
**Core Value:** Участник открывает сайт и сразу находит нужную запись; редактор правит её без потерь и без путаницы — и всё это выглядит как цельная «PORTIA OS».

Источник: открытые замечания ревью v1.0 (`.planning/milestones/v1.0-phases/*/…-REVIEW.md`), сверены с кодом в `.planning/research/FEATURES.md`. В скобках — закрываемые замечания.

## v1.1 Requirements

### Учёт замечаний

- [x] **TRIAGE-01**: Уже исправленные и устаревшие замечания закрыты с доказательством в записях ревью, без кода (01-CR-01, 05-IN-01, 05-IN-02, 05-IN-04, 05-IN-05, 03.2-IN-02, 03.2-IN-03 частично, старый 03.2 WR-03 `markQuestsSeen`)

- [x] **TRIAGE-03**: Перед правками сохранений владелец выгрузил `portia_employee_profiles` и `portia_content`; пункт STATE о переносе проекта закрыт (проект в `C:\Users\User\code\portia-site`)

### Сотрудники: сохранение без потерь

- [x] **EMP-01**: Сохранение сотрудника меняет только присланные поля: отсутствующее поле не меняется, пустая оценка очищает только оценку, неверный тип даёт 400; старый формат запроса принимается (03.1-WR-02, 03.2-WR-04, 03.3-IN-02)
- [x] **EMP-02**: Редактор отправляет только изменённые поля и сохраняет только при полностью прочитанном списке (`profilesRead === true`) — кэшированный или неполный список не стирает оценки (03.2-WR-02)
- [x] **EMP-03**: Сохранение профиля не зависит от Roblox и Google-таблицы: действующий сотрудник находится по таблице/базе, нет 404 и ожидания ~18 с (03.1-WR-03)
- [x] **EMP-04**: Сохранение деталей сотрудника вне таблицы не оставляет полузаписанного состояния и показывает верную причину ошибки (03.3-WR-03)
- [x] **EMP-05**: Текст, набранный во время сохранения, не теряется; ответ сервера не перезаписывает черновик другого сотрудника; таймер «СОХРАНЕНО» сбрасывается (03.2-WR-03, 03.1-WR-06)
- [x] **EMP-06**: При сбое чтения профилей или сотрудников вне таблицы посетитель видит последние хорошие данные, а кэш устройства не перезаписывается неполными (03.1-WR-01, 03.3-WR-02)
- [x] **EMP-07**: Исправленная ссылка на фото сотрудника показывается сразу, без перезагрузки (03.1-WR-05)
- [x] **EMP-08**: Кнопка «+ ВНЕ ТАБЛИЦЫ» доступна и при пустом списке сотрудников (03.3-WR-04)
- [x] **EMP-09**: Ник сотрудника вне таблицы хранится в написании Roblox; запрет удаления сотрудника из таблицы определяется кодом ответа, а не русской строкой (03.3-IN-01, 03.3-IN-04 часть 2)
- [x] **EMP-10**: 35-й и последующие сотрудники таблицы не пропадают молча — лимит виден или поднят (03.1-IN-03). Закрывается правилом (владелец, 2026-10-20, D-13): в таблице ровно 34 места (строки 2–35), строки после 34-го не заполняются; лимит не поднимается и не предупреждает, правило записано у staffRowsEnd в lib/portia-employees.ts.

### Синхронизация и целостность контента

- [x] **SYNC-01**: Опрос контента раз в 10 с не трогает редактор и рабочий стол, если ревизия не изменилась — история отмены сохраняется (03.1-WR-04, 03.2-WR-01)
- [x] **CONT-01**: Сохранение никогда молча не обрезает текст, гайды и таблицы: лимиты подняты и общие для редактора и сервера, у лимита кнопка «+» неактивна с подписью, сервер не отклоняет и не урезает существующие документы (03.1-WR-07 обрезка, 03.3-WR-01)
- [x] **CONT-02**: Новости, квесты и вирусы с полями неверного типа приводятся к правильному виду при сохранении и чтении, ничего не удаляя; `title: {}` не роняет сайт (03.1-WR-07 форма)
- [x] **CONT-03**: Окончательное удаление вируса или файла из Корзины удаляет и их форматирование; восстановление сохраняет форматирование (03.1-WR-08)
- [x] **CONT-04**: Новость, ставшая квестом, теряет «ВАЖНО»; квест никогда не показывает «ВАЖНО» (03.1-WR-09)
- [x] **CONT-05**: Отмена/повтор смены типа новость↔квест переключает вкладку «Сводки» на эту карточку (03.2-IN-04)
- [x] **CONT-06**: Квест с окончанием раньше начала исправляется или подсвечивается в редакторе, а не молча неактивен (03.1-IN-08)
- [x] **CONT-07**: С первой отрисовки квесты с датами показывают верный статус (03.2-IN-05)
- [x] **CONT-08**: Старый кэш контента без `recycledViruses` не роняет сравнение досье (03.1-WR-12)
- [x] **CONT-09**: Путь `//host/x.png` не считается локальным ни в коде, ни в SQL-проверке (03.1-IN-02)

### Устойчивость

- [x] **ROB-01**: Помощник с пустым или исчезнувшим советом не роняет рабочий стол; `FormattedText` переносит отсутствующий текст (03.1-WR-10)
- [x] **ROB-02**: Неверный или пустой JSON в API сотрудников, редакторов и контента даёт 400 с понятным текстом, а не 500 (03.1-IN-06, 03.3-IN-03, плюс `PUT /api/content`, `POST /api/editors`)
- [x] **ROB-03**: Побочные эффекты (localStorage, `setWindows`) вынесены из функций обновления состояния React (03.1-IN-09)

### Безопасность

- [x] **SEC-01**: Приложение пускает в редактор только пользователя с подтверждённой почтой (`email_confirmed_at`) — проверка в коде, работает до применения SQL (03.1-WR-11 код)
- [x] **SEC-02**: SQL требует подтверждённую почту в `portia_is_owner`/`portia_can_edit`; блок с предварительной проверкой `auth.users`, откатом и `begin/commit`; владелец проверил «Confirm email» в Supabase и применил SQL сам (03.1-WR-11 SQL)
- [x] **SEC-03**: Встроенные «Таблица», «Устав» и YouTube работают в `sandbox` с общим набором разрешений; проверено в браузере (03.1-IN-07, 03.3-IN-04 часть 1)

### Права редакторов (новое)

- [x] **PERM-01**: Владелец выдаёт доступ по email и для каждого редактора включает/выключает вкладки: База вирусов, Информация, Сводка, Корзина, Рекомендации, Помощник, Сотрудники
- [x] **PERM-02**: Новый и уже одобренный редактор по умолчанию имеет все вкладки; владелец может забрать любые
- [x] **PERM-03**: Редактор не видит закрытые для него вкладки
- [x] **PERM-04**: Сервер отклоняет правки закрытых разделов (контент и сотрудники), даже если запрос отправлен в обход интерфейса; SQL для прав применяет владелец

### «Устав»/«Таблица»: масштаб

- [x] **ZOOM-01**: Масштаб реагирует на Ctrl (на Mac и на Cmd), не реагирует на клавишу Windows; оверлей масштаба не залипает и не перехватывает клики (01-WR-02, 01-WR-03; решение владельца D-21)
- [x] **ZOOM-02**: Кнопка сброса масштаба озвучивает текущий процент (01-IN-03)

### Редактор и панель оформления

- [x] **EDIT-01**: На телефоне ГОТОВО без известного выделения не ставит курсор в начало — следующее ✎ не цепляет первое слово (05-WR-01)
- [x] **EDIT-02**: Бирюзовая метка цели заметна на светлом поле предпросмотра (контраст ≥ 3:1), проверено на ПК и телефоне (05-WR-06)

### Доступность и тексты

- [x] **A11Y-01**: Уведомление о квесте закрывается Escape без фокуса, имеет верные роли; список с ролями option (03.1-IN-04, 03.2-IN-01)
- [x] **A11Y-02**: Портрет Roblox имеет всплывающую подсказку; ручка ≡ остаётся без подсказки по решению владельца (01-IN-01; 01-IN-02 закрыт решением D-18)
- [x] **A11Y-03**: В редакторе нет шуточных и пустых надписей (03.1-IN-05)

### Тесты и порядок в коде

- [x] **TEST-01**: Ключ настроек — одна константа, тест запуска ловит расхождение (03.1-IN-01)
- [x] **TEST-02**: Тест на правило `::highlight` без заливки и граничный тест окна своего ввода; импорты `rich-text-style` объединены (05-IN-06, 05-IN-01, 05-IN-03)

### Пожелания владельца (добавлено 2026-10-25)

- [x] **BG-01**: Анимация фона рабочего стола плавная: спираль ДНК и паук двигаются без рывков, гель заметно движется, клетки ДНК не только крутятся, но и перемещаются и взаимодействуют друг с другом — проверено владельцем на ПК и телефоне
- [x] **THEME-01**: В настройках кроме четырёх готовых цветов можно выбрать свой через тот же выбор цвета, что и в редакторе; свой цвет применяется ко всему, что берёт акцент (паук, значки, рамки и т. д.) и сохраняется между заходами
- [x] **EDIT-03**: Разделы и подразделы редактора сворачиваются и разворачиваются; между разделами можно быстро перейти, не прокручивая всё; порядок разделов легко менять даже при большом их числе
- [x] **EDIT-04**: Панель оформления текста — свободное окно, которое можно двигать по рабочему столу, а не только внутри окна редактора, чтобы она не закрывала обзор
- [x] **EDIT-05**: Плашка «НЕ СОХРАНЕНО» компактная и не закрывает обзор (особенно на телефоне) — меньше по размеру или вынесена туда, где не мешает
- [x] **EDIT-06**: Можно выделить несколько фрагментов текста с Ctrl; выбранное оформление (например, цвет) применяется ко всем выделенным фрагментам сразу
- [x] **EDIT-07**: В таблицах редактора можно менять порядок строк (и столбцов — уточнить в обсуждении фазы)

### Движение и значки на Motion (добавлено 2026-10-26, без своей фазы)

Пакет `motion` уже установлен (`package.json`). Брать в работу после Phase 11, когда горячие файлы свободны; «простые» циклы остаются на CSS, Motion — там, где нужны пружины, исчезновение и перестроение.

- **MOTION-01**: Паук двигается живее и естественнее (пружинное движение, без рывков) — `components/portia-wallpaper-spider.tsx`
- **MOTION-02**: Окна рабочего стола открываются, закрываются, сворачиваются и перетаскиваются плавно, с анимацией исчезновения — `components/portia-desktop.tsx`
- **MOTION-03**: Фон рабочего стола движется плавнее — только если это заметно лучше нынешней CSS-анимации (BG-01); иначе фон остаётся на CSS — `components/portia-wallpaper.tsx`, `app/portia.css`
- **MOTION-04**: Все значки приложений нарисованы заново в едином стиле (сама отрисовка — не Motion, а дизайн; Motion — только их анимация при наведении и запуске) — `components/portia-icons.tsx`
- **MOTION-05**: Все новые анимации выключаются при `prefers-reduced-motion`
