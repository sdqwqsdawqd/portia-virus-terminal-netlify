<objective>
SEC-03, успех 2 ROADMAP: проверка после сборки ищет маркеры содержимого в `.next` и роняет сборку при находке. Трассер — один путь через все слои: скрипт скана → npm-хук `postbuild` → реальная сборка → `.next` → код выхода. Вторая задача закрепляет маркеры против дрейфа (есть в фикстуре, нет в рабочем коде) и печать только путей.

Purpose: 25-RESEARCH.md §3 нашёл «МОРОК» в клиентском чанке, серверных чанках и картах исходников прежней сборки; после удаления сида (план 25-06) скан — постоянная защита, чтобы стартовые записи не вернулись в сборку через новый импорт.
Output: `scripts/phase25-build-scan.mjs`, `lib/phase25-build-scan.test.ts`, `postbuild` в `package.json`.

Решения (Claude's discretion: маркеры и подключение):
- Обычный ESM `.mjs` без импорта TS (Netlify собирает на Node 22.13.0 без флага strip-types); маркеры — литералами в скрипте, синхронность с фикстурой проверяет тест.
- `.claude/skills/portia-check/run.sh` не меняется: он не отслеживается git (`.git/info/exclude`), а его режим `build` вызывает `npm run build`, после которого `postbuild` срабатывает сам.
- Если `npm run build` под эталонным Node не запускается (прецедент 24-BROWSER-EVIDENCE.md: сломанный `npm` во временном Node), сборка — `node node_modules/next/dist/bin/next build`, затем явный `node scripts/phase25-build-scan.mjs`; это записывается в SUMMARY. Значения окружения не печатаются, `.env*` не читаются агентом; при нехватке переменных сборки — выдуманные значения `OFFLINE_ENV` из `tests/e2e/harness/offline-supabase.cjs` в окружении процесса (как `scripts/phase20-release-gate.mjs`).

Red-window gate (как во всех планах до 25-10): `node --experimental-strip-types --test --test-skip-pattern="matrix freshness: the real matrix commit" --test-skip-pattern="migration coverage: the real matrix has exactly one row" lib/*.test.ts`.
