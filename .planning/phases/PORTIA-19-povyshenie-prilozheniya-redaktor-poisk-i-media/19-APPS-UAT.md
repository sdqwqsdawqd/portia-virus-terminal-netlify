## Перед началом (важно, сделайте по порядку)

1. **Не запускайте свой `npm run dev`.** В 19-06 ваш dev-сервер молча читал `.env.local` с production и изменил боевые данные. Для этой проверки сервер с окружением изолированного staging запускает оркестратор из своего процесса. Адрес: **https://192.168.10.3:3000** (PC и phone в одной сети).
2. Браузер покажет предупреждение о сертификате (локальный сертификат разработки): примите его («Дополнительно» → «Продолжить»).
3. **Очистите данные сайта** для `192.168.10.3` перед проверкой: PC (Chrome/Edge): значок слева от адреса → «Настройки сайта» → «Удалить данные», либо DevTools → Application → Storage → «Clear site data»; phone: настройки браузера → «Настройки сайта» → адрес `192.168.10.3` → «Удалить данные». Без этого старый кэш приложений скроет состояние «загрузка» и «нет связи».
4. **Не входите со своей реальной учётной записью** и не вводите реальные ники. Сайт на этом адресе смотрит на staging; живая Google-таблица для списка сотрудников остаётся боевой (только чтение).
5. PC: проверьте на DPR 1 и, если есть, на DPR 1.25 (масштаб Windows 125%). Phone: свой телефон по тому же адресу.
6. Отключение сети после загрузки (для «stale» и «fatal»): PC: DevTools (F12) → вкладка Network → «Offline»; phone: режим «В самолёте» или выключить Wi-Fi.

Данные на staging (по прогонам): 3 вируса, 4 раздела «Информации», 3 файла в «Корзине», около 16 сотрудников; в «Справочнике» нет карточек и в «Сводке» нет записей.
