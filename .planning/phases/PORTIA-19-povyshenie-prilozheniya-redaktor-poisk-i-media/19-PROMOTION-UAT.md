## Подготовка (до начала, выполняет владелец)

1. Запусти приложение так, чтобы процесс `npm run dev` видел переменные ИЗОЛИРОВАННОГО проекта (не production):
   - `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` проекта staging;
   - `PORTIA_PROMOTION_DEVICE_SECRET` (не короче 32 символов);
   - `PORTIA_PROMOTION_STAGING_ROSTER` = путь к `roster.json` из таблицы выше;
   - `PORTIA_E2E_ISOLATED_PROJECT_IDS` = ref staging; `PORTIA_E2E_PRODUCTION_PROJECT_IDS` = ref production (непустой, не совпадает с staging).
   Если URL указывает не на изолированный проект, ростер молча отключается (`lib/portia-promotion-staging-roster.ts`), и временные ники будут «не найдены». Это безопасно, но прогон бессмыслен. Не запускай против production, не меняй банки на production.
2. Доступ с телефона (одна сеть Wi-Fi с ПК): запусти `npm run dev -- -H 0.0.0.0` (по умолчанию `next dev` уже слушает 0.0.0.0), узнай IPv4 ПК (`ipconfig`, адаптер Wi-Fi), открой на телефоне `http://<IPv4>:3000`. Разреши Node.js во входящих правилах брандмауэра Windows для частной сети.
3. ВАЖНО, риск для phone: cookie привязки устройства выставляется с атрибутом `Secure` (`lib/portia-device-binding.ts:29`). На PC по адресу `http://localhost:3000` браузер его принимает. На телефоне по `http://<IPv4>:3000` (не HTTPS и не localhost) браузер его отвергнет, и «reload восстанавливает ник» (STAB-PROM-03) на phone пройти не сможет, это не дефект кода, а ограничение среды. Чтобы проверка phone была честной, нужен HTTPS: `npm run dev -- --experimental-https` (сертификат создаёт mkcert из Next.js; на телефоне его нужно доверить) либо вариант B из решения 2 (deploy preview на Netlify со значениями staging). Выбор среды за владельцем; пока выбор не сделан, шаги с привязкой на phone нельзя записывать как PASS.
4. Next.js 16 блокирует dev-only запросы с чужих origin; если на телефоне страница не оживает (не гидратируется), агенту нужно добавить `allowedDevOrigins` с IPv4 ПК в `next.config.ts` отдельной правкой. Напиши агенту, если так.
5. Clean reload на каждом устройстве перед своим прогоном: очистить кэш и cookie сайта.
6. На staging ничего вручную не создавай и не удаляй вне самого потока: teardown (19-07) удаляет всё, созданное после `createdAt` манифеста, а лишние записи портят доказательство нулевого остатка.

## Как просить сдвиг дат (D-03)

Скажи в чате: «нужен сдвиг <kind> [label]». Агент выполнит строго `node --experimental-strip-types scripts/phase16-staging.mjs acceptance-shift mvz5fqgv_c40b449b <kind> [label] [value]` и запишет время и kind в журнал ниже. Допустимые kind: `cooldown <label>`, `rank <label> <titleId>`, `penalty`, `cleanup`, `deadline [label]`, `retake [label]`. Правила и длительности в коде и SQL не меняются, сдвигаются только даты этого run.

Ограничение: ники одноразовы. Если на проходе phone ник уже исчерпан состоянием после PC (ordinary подтверждён, заявка закрыта), агент сообщит об этом, и решение (сдвиг `rank`, другой ник, новый run после teardown) за владельцем. Ничего не пересеивается без твоего решения.
