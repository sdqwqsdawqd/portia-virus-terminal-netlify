# 19-OWNER-DECISIONS: решения владельца по [PROPOSED] и допущениям Phase 19

**Дата сбора:** 2026-11-02
**Статус:** вердикты владельца записаны 2026-11-02 («все рекомендации»): по всем 11 пунктам принята рекомендация агента.

Правило: пункт [PROPOSED] не реализуется до записанного вердикта (STAB-APP-10). Вердикт владельца пишется в строку вердикта дословно. Ключей, ref проекта и реальных ников в документе нет и быть не должно.

Что значат пометки: **A / B** — варианты; **Рекомендация** — выбор агента; **Fallback** — что будет, если владелец отказал или не ответил; **Reversibility** — насколько дорого передумать позже.

## 1. Источник ростера для временных участников приёмки (D-01)

**Суть.** Ростер участника сервер читает из боевого Google Sheet (`lib/portia-promotion-sheet.ts`). Временного ника приёмки в таблице нет, поэтому сервер ответит «не найден», и поток «Повышения» на staging не пройти.

**Варианты.**
- **A (рекомендация).** Серверная переменная `PORTIA_PROMOTION_STAGING_ROSTER` с путём к JSON-ростеру, который пишет seed. Учитывается только если одновременно: `NEXT_PUBLIC_SUPABASE_URL` указывает на проект из `PORTIA_E2E_ISOLATED_PROJECT_IDS`; проект не входит в непустой `PORTIA_E2E_PRODUCTION_PROJECT_IDS`; `CONTEXT` не равен `production`. Ники вида `__portia_live_<runId>_p1`, по ним teardown находит свои записи.
- **B.** Реальные ники владельца из таблицы на staging-базе. Переходы ограничены реальными званиями, «смена звания» не проверяется.
- Отклонено: «добавить строки в боевую таблицу» — это мутация production-источника (CLAUDE.md, жёсткое правило).

**Fallback при отказе от A.** Вариант B.
**Reversibility.** costly: A меняет серверный код ростера, и откат после приёмки потребует отдельной чистки.

Вердикт: Владелец (Qloxz), 2026-11-02: принята рекомендация — A (ростер через PORTIA_PROMOTION_STAGING_ROSTER, только изолированный staging)

## 2. Где владелец запускает приложение, привязанное к staging (PC и phone)

**Суть.** Для приёмки нужно приложение, смотрящее на изолированный staging, а не на production. Агент даёт инструкцию, выбор среды за владельцем.

**Варианты.**
- **A.** Локальный `npm run dev` на ПК владельца; телефон заходит по LAN на адрес ПК. Переменные staging лежат в локальном `.env.local`, агент их не читает и не печатает.
- **B.** Deploy preview на Netlify с переменными staging. Доступен с любого устройства, но нужен отдельный deploy и значения staging в настройках сайта.

**Рекомендация.** A: быстрее, ничего не уходит наружу.
**Fallback.** A.
**Reversibility.** cheap.

Вердикт: Владелец (Qloxz), 2026-11-02: принята рекомендация — A (локальный npm run dev по LAN)

## 3. Клавиатура глобального поиска (STAB-SEARCH-03) [PROPOSED]

**Суть.** Таблица из 19-UI-SPEC: Ctrl/Cmd+K — открыть/сфокусировать поиск; Tab — поле, рекомендации, результаты (без ловушки); ↓/↑ — между результатами, ↑ с первого возвращает в поле; Enter — открыть результат (в поле при единственном результате — открыть его); Escape — очистить запрос, в пустом поле закрыть окно.

**Варианты.** A: утвердить таблицу целиком. B: утвердить с правками (указать клавиши).
**Рекомендация.** A.
**Fallback.** Только существующий порядок Tab и Enter, без Ctrl/Cmd+K, стрелок и Escape-логики.
**Reversibility.** cheap: одна правка обработчика.

Вердикт: Владелец (Qloxz), 2026-11-02: принята рекомендация — да

## 5. «Заменить своей» без отдельного диалога (D-09) [PROPOSED]

## 6. Подтверждения в «Повышении» (итог проверки, удалить вопрос/запрос, снять claim) [PROPOSED]

**Суть.** Итог проверки необратим; удаление вопроса/запроса и снятие claim тоже разрушительны.

**Варианты.**
- **A (рекомендация).** Существующий диалог PromotionConfirmDialog с подписями из UI-SPEC: «Подтвердить итог» / «Не подтверждать»; «Удалить вопрос» / «Оставить вопрос»; «Удалить запрос» / «Не удалять»; «Снять claim» / «Не снимать».
- **B.** Подтверждение в строке («Подтвердите итог: …» и две кнопки) без modal.

**Fallback.** A.
**Reversibility.** cheap.

Вердикт: Владелец (Qloxz), 2026-11-02: принята рекомендация — A

## 10. Тексты участника «Повышения»

**Суть.** UI-SPEC предлагает «Ник не найден в таблице. Проверьте написание.» и «Таблица со списком временно недоступна. Ник не проверен — попробуйте позже.» Сервер уже отдаёт различимые тексты по кодам `not-listed`, `sheet-unavailable`, `pending-database`, `promotion-rollout-incomplete`, `promotion-database-unavailable`; сейчас, например, `not-listed` = «Ник не найден в списке PORTIA. Проверьте написание или обратитесь к руководителю.», `sheet-unavailable` = «Список участников временно недоступен. Попробуйте позже — заявка не отправлена.»

**Fallback.** B.
**Reversibility.** cheap.
