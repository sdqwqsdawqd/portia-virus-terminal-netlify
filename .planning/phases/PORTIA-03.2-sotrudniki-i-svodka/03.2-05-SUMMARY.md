# Phase 03.2 Plan 05: Quest popup Summary

A published, active quest the visitor has not seen pops up once in a separate «НОВЫЙ КВЕСТ» window after the boot screen and never again after any dismissal, across reloads, live content updates and unreadable or unwritable storage.

## What was built

- **lib/broadcasts.ts:** `parseSeenQuestIds` (only an array of strings counts, everything else is `[]`), `questPopup(list, seen, today)` (first published `quest` in editor order whose `questState` is active and unseen, plus `more` = the other unseen active ones; tasks, news, upcoming, finished and unpublished are never returned; an upcoming quest becomes the popup on its start day), `markQuestsSeen(list, seen, today)` (stored ids that still exist in the list plus every active published quest, no duplicates). 5 new test cases, 123 tests pass.
- **components/portia-desktop.tsx:** `QuestPopup` copies the editor's ConfirmDialog pattern (ref, `showModal()` in an effect, focus on the `data-autofocus` button, `onClose` and backdrop click dismiss). It shows the eyebrow, title (or «БЕЗ НАЗВАНИЯ»), only the dates that are set, «УСЛОВИЯ» as React text, the body through `FormattedText` with its stored document, «Ещё активных квестов: N» when more than one, and «ОТКРЫТЬ КВЕСТЫ» / «ПОНЯТНО» (autofocus). The popup effect is gated by `contentReady && !booting && !windows.editor.open && today && !questPopupItem && !questReadBlocked`; unreadable storage sets `questReadBlocked` and shows nothing. `rememberActiveQuests` (shared by dismissal and view) merges storage with the ref, calls `markQuestsSeen`, updates the ref first and writes in try/catch; if the read threw it does not write.
- **Task 2 behaviours** (implemented together with Task 1 because they share the helper): while «Сводка» is open, not minimized and on «Квесты», and `contentReady`, the active quests are marked seen. That effect is declared before the popup effect, so a live update the visitor is already reading does not pop up. The popup effect depends on `content.broadcasts`, so a quest published during the visit pops up once without reload and the ref keeps it dismissed.
- **app/portia.css:** `.quest-popup` width `min(520px, calc(100vw - 24px))`, max-height `calc(100svh - 48px)` with scroll, body capped at 40vh with its own scroll; eyebrow joins the existing quest amber rule (no new colour literal); `.broadcast-dates` / `.broadcast-conditions` reused. Entrance animation `fade-in` (existing keyframe) only under `html[data-motion="full"] .quest-popup[open]`, so soft mode shows the window instantly. Actions reuse `.portia-dialog-actions` (flex-wrap, buttons min 40px).
