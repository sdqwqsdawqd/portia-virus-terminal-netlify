# Phase 03.2 Plan 02: Employee draft guard Summary

Unsaved employee edits are never dropped silently: switching employee, switching editor tab, closing the editor (×) and reloading all ask first (reload via the browser's own warning).

## Accomplishments

- `profileChanged` in `lib/portia-employees.ts`: biography, photo and all six ratings, null equals a missing new rating, whitespace counts. Three test cases (identity/legacy, each field via `employeeRatings`, whitespace).
- `EmployeeProfilesEditor`: `dirty` from `profileChanged(profileOf(selected), draft)`; `save()` now resolves `true` only on success. One `ConfirmDialog` («Несохранённые правки сотрудника») serves the pending employee switch and the tab / window leave. ОТМЕНА is the default focus; a failed save closes the dialog and leaves the error text on the current employee.
- `PortiaEditor`: `employeeDirty` + `leaveTo`; `switchTab` asks first when leaving «Сотрудники» dirty; the desktop is told `dirty || employeeDirty` so × asks; the content «Закрыть редактор?» dialog renders only when `closeAsked && !employeeDirty`, so it follows the employee answer when the content is dirty too.
- Clean drafts behave exactly as before. `components/portia-desktop.tsx`, `app/api/content/route.ts`, `lib/content-sync.ts`, `lib/editor-items.ts` untouched.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Clicking the same employee with a dirty draft would have reset it**
- **Found during:** Task 1
- **Issue:** the plan calls `openEmployee` directly for the same employee; `openEmployee` replaces the draft with the saved profile, silently dropping the edits.
- **Fix:** with a dirty draft, clicking the selected employee only opens the record view (phone) and keeps the edits.
- **Files modified:** components/portia-editor.tsx
- **Commit:** 95cd6da

**2. [Rule 1 - Bug] НЕ СОХРАНЯТЬ and a list click during a sent save**
- **Found during:** Task 1
- **Issue:** the PATCH answer calls `setDraft(profileOf(saved))`, which would overwrite the next employee's draft if the user switched while it was in flight.
- **Fix:** НЕ СОХРАНЯТЬ is disabled while saving (as in the content dialog) and a list click is ignored during a save; the post-save continuation checks a ref so a cancelled question never continues.
- **Commit:** 95cd6da

**3. [Rule 2 - Missing critical] Dirty flag cleanup on unmount**
- **Fix:** `EmployeeProfilesEditor` reports `onDirtyChange(false)` on unmount so the parent can never keep a stale `employeeDirty`.
- **Commit:** 31bb67c
