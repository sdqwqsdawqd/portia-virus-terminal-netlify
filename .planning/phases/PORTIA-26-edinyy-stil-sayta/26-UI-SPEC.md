## Spacing Scale

Standard 4-point scale for every **new or unified** rule of the five shared families (button, field, plaque, tab, list row) and the editor-tab layout. Page, section and dossier paddings elsewhere are **not rewritten** (spacing is out of boundary).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between plaques; gap between caption lines; tab gap (existing) |
| sm | 8px | Gap between buttons; gap between grid cards; label → control; bar item gap |
| md | 16px | Horizontal padding of button, tab, list row, bar; section padding in the form pane |
| lg | 24px | Gap between form columns; gap between blocks in the detail pane |
| xl | 32px | Detail-pane outer padding at ≥901px |
| 2xl | 48px | Action-bar height; empty-state vertical padding |
| 3xl | 64px | not used |

Exceptions (all existing values or required geometry, none decorative):

- Control heights: **40px** (button, tab, field on PC; matches today's 39/40 mix), **32px** compact (dense rows on PC only), **44px** at ≤900px (existing `--tap-target`). The 32/36/39/40/42 mixture of today is replaced by these three.
- Field horizontal padding 8px 16px (today 10px 12px / 8px 12px).
- Layout caps (multiples of 4, new): field max width **640px**, grid card min width **360px**, list pane `clamp(240px, 24%, 320px)`, two-column form wrapper max **1320px**, reading column max **820px**.
- Close cross hit area **46×46** on windows (equals title-bar height), **44×44** elsewhere.
- 1px borders; 3px active-tab inset line; 2px focus ring (existing).
- Row padding for lists is `8px 16px` (replaces today's 7/11/13px in `.editor-record-list button`, as promised in 22-UI-SPEC "Phase 26 unifies").

New layout tokens go next to the radius tokens in the first `:root`: `--control-height: 40px; --control-height-compact: 32px; --field-max: 640px; --card-min: 360px;`. `--tap-target: 44px` already exists and starts being read.

## Typography

Declared for the shared families only; the rest of the site keeps its type. **Three sizes (11 / 13 / 16), two weights (400 / 700).** All three already exist on the site (`.app-fatal-panel strong` and `.access-redacted-title` are 16/700; dialog titles and list titles are 12–13px; buttons, plaques and tabs are 11px).

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Label | 11px | 700 (400 for captions, hints, bar status) | 1.35 | Buttons (letter-spacing .04em), plaques (.09em), tabs (.04em), captions, field hints, bar status |
| Body | 13px | 400 | 1.55 | Dialog and pane text, empty-state body, field text on PC, current-section name in the phone bar |
| Body strong | 13px | 700 | 1.35 | List-row title, dialog title (letter-spacing .04em, existing) |
| Heading | 16px | 700 | 1.35 | Detail-pane title, empty-state heading (the existing `.app-fatal-panel strong` look) |
| Display | not used | | | |

Hierarchy is carried by three steps (11 label, 13 body, 16 heading) plus weight; there is no 12px role (12px list titles and the current-section name move to 13px, so the old 11/12/13 near-duplicates are gone). Native inputs and selects at ≤900px are 16px (the existing iOS-zoom rule); that is the Heading size, not a fourth one. Field hints move from 10px to 11px (the Label size) as part of the UI-10 hint fix. Glyphs `―`, `□`, `×` and `▾ ▴` are **icon glyph sizes (18–20px), not type sizes**; they are `aria-hidden` and carry no text. Tab text 12px/600 becomes 11px/700; no other weight (500, 600) is used by a shared family. Letter-spacing values are the existing ones. Button, tab and plaque text keep the case the copy already has; no `text-transform` is added. These changes to type are recorded as Assumption A9.

### Assignment rule (by role, never by old value)

Every `border-radius` in `app/*.css` is edited in place to a role token. If a role is not listed in a table: interactive action → control; text / number input → field; non-interactive label, status or count → plaque; bordered container holding content → card; floating layer over content → dialog; whole application surface → window; dot or round glyph → round. Compound radii are allowed only as a space-separated composition of role tokens or `0`, for example the assistant bubble `var(--radius-dialog) var(--radius-dialog) 0 var(--radius-dialog)`. The literal `0` stays legal.

- Title bar `padding-right: 0`. `.window-controls` has `gap: 0` and sits flush right; its three buttons are **46×46px** (the existing title-bar height of 46px; recorded as a legacy exception to the 44px minimum rather than a geometry change: the bar is not resized, the hit area simply fills it), `border-radius: var(--radius-control)` (0), no individual border except a 1px left divider `var(--line)`, background transparent; hover = existing neutral hover for minimise/maximise and the existing danger hover (`#5d2d29`, border `#a65750`) for close. - The close button is the last element, in the **extreme top-right corner**. The window's 10px radius and `overflow: hidden` clip its top-right corner; that is intended.
- Controls render above the resize edges: `.window-controls { position: relative; z-index: 10 }` (edges are `z-index: 9`). The NE resize corner is therefore inert under the controls; N and E edges still resize.
- Same rule for every window-like layer with a cross, through one shared class `.corner-close` (44×44, flush `top: 0; right: 0`, sharp, `×` as a 20px icon glyph): `.access-close` in the access card (today `top: 12px; right: 12px`), the quest-toast close, the custom colour picker close, the floating text-format panel close. - Locked windows, phone windows and maximized windows all keep the same corner geometry.

### Maximized window (D-01 … D-04)

`.app-window.is-maximized` (`inset: 8px`, 10px radius via `--radius-window`) is unchanged and remains the only hook (D-03). **Do not set `container-type` on `.app-window` or on any ancestor of `position: fixed` or sticky descendants** (it re-anchors fixed elements such as the phone `.editor-save-chip` and toasts). Widths are therefore driven by `.app-window.is-maximized` plus viewport media, not container queries.

Recipes (copy, do not improvise):

| Id | Rule | Result |
|----|------|--------|
| R1 Card grid | `.app-window.is-maximized <list> { display: grid; gap: 8px; grid-template-columns: repeat(auto-fill, minmax(max(var(--card-min), calc((100% - 24px) / 4)), 1fr)); }` | 360px minimum, **at most 4 columns**, 2–4 on 1366–2560px screens; a normal-size window keeps the single column |

## Editor Tab Layout (UI-04, D-12, D-13)

One layout for every editor tab, including «Справочник», «Повышение» and «Пользователи».

### Structure

```
.etab                      grid, rows: [action bar: auto] [body: 1fr]; fills the tab area
 ├─ .etab-bar              sticky; [nav] [status] [actions]
 └─ .etab-body             grid, cols: [list pane: clamp(240px, 24%, 320px)] [detail pane: minmax(0, 1fr)]
      ├─ .etab-list        record list (the existing .editor-record-list look)
      └─ .etab-detail      form or detail (R3 two columns when maximized and ≥1281px)
```

- A tab with no list (Помощник, Доступ) renders only the detail pane: **no empty left column**. A tab with no sections renders no nav slot.
- The top-level tab strip (`.editor-tabs`) stays above and switches tabs; the bar's nav switches sections **inside** a tab.

### Action bar (D-13b: sticky)

- `position: sticky; top: 0; z-index: 3` (below dialogs and toasts), opaque `var(--panel)` background, 1px bottom border `var(--line)`, `min-height: 48px`, padding `0 16px`, gap 8px, no blur.
- Slots left to right: **nav** (`flex: 1 1 auto`, `min-width: 0`, horizontal scroll, no wrapping) · **status** (`flex: 0 1 auto`, 11px, `role="status" aria-live="polite"`, ellipsis) · **actions** (`flex: none`, gap 8px).
- Draft tabs: actions = `ОТМЕНИТЬ` (secondary, `disabled` while clean or saving) and `СОХРАНИТЬ` (primary, `disabled` while clean or blocked); status = `saveStatusText(status)` (existing vocabulary, plus `Не сохранено: N` count while dirty). Non-draft tabs (Пользователи, Корзина, parts of Повышение) show **no** Сохранить/Отменить (absent, not disabled); their one primary action (for example owner `ОДОБРИТЬ ИЗ ТАБЛИЦЫ`) takes the actions slot and the status slot shows their own state («Ожидают: N»).
- `ОТМЕНИТЬ` opens the **existing** discard `ConfirmDialog` («Отменить несохранённые правки?», `ВЕРНУТЬ СОХРАНЁННОЕ` danger / `НЕ ОТМЕНЯТЬ` safe, autofocus). Ctrl+Z/Y behaviour and the undo-step button are unchanged (the undo `↶` moves into the actions slot as a secondary icon button 40×40, `aria-label="Отменить последнее действие"`).
- Error and refusal reasons that lived in the chip popover (`saveError`, oversize, body message, bad quest date fix link) render as `role="alert"` lines directly under the bar (`.etab-message`), not in a popover. The sr-only live region listing unsaved sections stays.
- The floating `.editor-save-chip` + popover is **retired** for tabs that use the bar. Its two unsaved-section affordances move to the status text and the tab-strip dot.
- Phone (≤900px): the bar wraps into two rows inside **one** sticky element (row 1: status + actions at 44px, row 2: nav at 44px, horizontally scrollable). It uses the existing `overflow: clip` mechanism for `.app-window` / `.content-editor` so sticky holds against the page; its `top` equals the offset `.editor-section-addbar` uses on phone today (48px under the system bar; read it, do not guess). The fixed phone chip's `bottom` offsets that cleared the text-format panel are removed with it.

## Assumptions and Open Points (no owner available during this session)

- **A1 Spacing of shared families.** CONTEXT keeps "spacing" unchanged. This spec unifies only the box model of button, field, plaque, tab and list row (40/32/44px heights, `8px 16px` rows), which belongs to "the look of buttons, plaques, tabs"; page and dossier paddings are untouched. Report this to the owner as text.
- **A2 Chips are plaques.** Search suggestion chips and type marks stay pills (plaque), not sharp buttons; they only fill the search or label a type. If the owner reads "buttons are sharp" literally, this is a one-line change on one screen.
- **A3 Stacked actions on phone.** In containers narrower than 480px a stacked action list may fill the width (Users phone action window, phone dialogs). D-02 forbids stretching; this is read as applying to wide windows, and stacking in a narrow column creates no empty band.
- **A4 Users on PC.** Moving Phase 22's inline row actions into a detail pane is the reading of D-12 ("all tabs including Пользователи use one layout"). It costs one-click bulk approval per row on PC; the owner-only `ОДОБРИТЬ ИЗ ТАБЛИЦЫ` stays one click, and next-row selection after a decision keeps single approvals to one click + one click.
- **A5 Icon artifact vs. "no drawing".** D-06 shows 15 icons per style on an artifact page; D-09 says no drawing before the pick. Read here as: the artifact is presentation outside the repo, the repo is not touched until G-ICON-2. If the owner meant "no drawing of any kind before the pick", the artifact shows representative samples per style instead; the planner confirms with the owner in the checkpoint text.
- **A6 Reading column.** R4 caps long text at 820px, so very wide maximized windows have side margins on reading surfaces. This is a typographic measure, not an unused band, but it is the first thing the owner may call "empty space".
- **A7 Contrast values.** The `.eyebrow` and hint fixes name the target thresholds and colours; the test, not this spec, is the authority on each accent.
- **A9 Type changes inside a «fonts stay» phase.** CONTEXT keeps fonts unchanged (family, palette, animations). This spec keeps every font family and reduces the sizes the shared families use to three (11/13/16) so the type scale stays small: tab text 12px/600 becomes 11px/700 (one weight pair, 400/700), list-row titles and the phone current-section name 12px become 13px, field hints 10px become 11px (also the UI-10 hint fix). These are small, shared-family adjustments, not a re-typesetting; report them to the owner as text. If the owner objects, the fallback is to keep 12px tabs and name them as a documented exception.
- **A10 Close-cross size.** The 46×46 hit area equals the existing 46px title bar (legacy exception to the 44px rule; the bar is not resized). Other close crosses are 44×44.
- **A8 Save chip retirement.** Retiring the popover removes the "list of unsaved sections" popup; the information moves to the status text, tab dots and the sr-only live region. If the owner misses the list, a `title`-only tooltip on the status is the cheapest addition.
