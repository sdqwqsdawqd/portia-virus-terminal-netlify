Как поднять BASE рядом с рабочей копией (Claude `.env.local` не читает и не копирует, файл кладёте вы):

1. `git worktree add ../portia-perf-base 78c24e1fc95d4a2bccfe22e6b6852262ef93e32f`
2. В папке `../portia-perf-base`: `npm ci`, затем положить свой `.env.local` (только тестовые значения, не production).
3. `npm run build`, затем `npm start`, открыть адрес из вывода.
4. После замера: `git worktree remove ../portia-perf-base`.

«После» снимается тем же способом на HEAD (в основной копии или во втором worktree), с теми же настройками.

## Условия замера PC

Chrome, DevTools, вкладка Performance. Без CPU throttling, масштаб экрана как обычно; отметьте, что у вас: DPR 1 или DPR 1.25. Настройки рабочего стола: обои «Паутина», паук «Показывать», «Анимации: Включены». Один trace на сценарий:

1. **PC-1.** Открыть «Глобальный поиск» с ярлыка.
2. **PC-2.** Тащить окно за заголовок 3 секунды.
3. **PC-3.** Сменить обои Паутина, затем Гель, затем снова Паутина.
4. **PC-4.** Долгая сессия: вкладка открыта не меньше 10 минут, затем сценарий PC-1 ещё раз.

## Условия замера phone

Android Chrome через `chrome://inspect` (remote debugging, вкладка Performance) или iPhone Safari через Web Inspector, Timelines. Те же настройки рабочего стола. Сценарии:

1. **Phone-1.** Открыть «Глобальный поиск» с ярлыка.
2. **Phone-3.** Сменить обои Паутина, Гель, Паутина.
3. **Phone-taskbar.** Переключение окон через панель задач.

## Что выписать из каждого trace

- самый длинный кадр, мс;
- число кадров дольше 50 мс;
- длительность взаимодействия, мс (клик до следующего кадра).

## Budget (D-17)

- На типовых действиях нет кадров дольше 50 мс.
- «После» не хуже «до»: число кадров дольше 50 мс после не больше, чем до; самый длинный кадр после не больше max(до, 50 мс).
