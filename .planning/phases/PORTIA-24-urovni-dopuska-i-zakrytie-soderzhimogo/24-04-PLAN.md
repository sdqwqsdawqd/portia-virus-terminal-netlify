<objective>
Изменение уровня и отзыв доходят до посетителя при следующем обновлении без перезагрузки (LVL-09, D-21, D-22, D-23), кэш устройства не хранит чужой уровень (LVL-05), а записи учёных у посетителя читаются по реальному уровню на шкале 1–5 и без пустого блока (LVL-06, LVL-07, D-12, D-14, D-15).

Purpose: сервер уже отдаёт копию по зрителю (24-01); без правил приёма и кэша клиент отбрасывал бы ответ той же ревизии и показывал бы старую копию более высокого уровня.
Output: правила синхронизации и кэша, проводка шлюза и рабочего стола, досье на реальном уровне.

Порядок с планом 24-05 (объявлен, а не подразумевается). Досье этого плана считает запись учёного закрытой только по серверному признаку `withheld`, а ставит этот признак (и убирает текст закрытой записи из ответа) серверная очистка плана 24-05 (волна 3). Этот план от 24-05 не зависит ни по файлам, ни по сборке: тип `withheld?: true` уже есть после 24-01, а тесты Task 3 проверяют клиентскую сторону на фикстурах и исходниках с `withheld: true`. Поэтому здесь доказывается только «строка закрыта ⇔ `withheld`, текст не рисуется»; сквозное поведение записей учёных (сервер ставит `withheld` → у посетителя «ЗАБЛОКИРОВАНО», текста нет в ответе) доказано только после 24-05 — его тестами-приманками D-12 и связкой key_links 24-05 → `components/portia-desktop-dossier.tsx`. Между коммитами 24-04 и 24-05 сервер ещё отдаёт записи учёных без `withheld` и с текстом (как до фазы), поэтому досье показывает их открытыми: это промежуточное состояние ветки внутри фазы, оно не выкатывается (включение закрытия на production — Phase 25), и проверка фазы (24-11) идёт только после 24-05.

Решения планировщика (Claude's discretion из CONTEXT): ключ зрителя — `editor` или `level-N`; приём ответа — новее по ревизии **или** другой зритель; порядок ответов — по номеру запроса (поздний старый ответ отбрасывается); кэш показывается только при точном совпадении ключа; интервал редактора 10 с, посетителя 30 с. Очистка кэшей при любом решении «закрыто и не допущен» — это D-21 для отзыва; полный браузерный тест очистки при каждом переходе в неодобренное (SEC-04) остаётся Phase 25.
