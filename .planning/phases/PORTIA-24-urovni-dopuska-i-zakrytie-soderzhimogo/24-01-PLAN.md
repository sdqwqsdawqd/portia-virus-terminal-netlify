Трассер фазы: одна закрытая запись «Базы вирусов» проходит все слои — сохранённое поле `level` → нормализатор → серверная очистка → GET /api/content по зрителю (no-store, `viewer`) → клиентская нормализация с маркером `redaction` → строка «ЗАСЕКРЕЧЕНО · нужен допуск N» на её позиции. Вторая задача доказывает тот же путь тестами-приманками для уровней 1–5 и разрешённым списком префиксов `formattedText`.

Purpose: доказать архитектуру «сервер отдаёт только разрешённое, UI рисует пришедшее» на самом коротком пути, прежде чем расширять очистку на «Информацию», «Справочник», «Корзину», поиск и «Устав».

Всё, что не лежит на этом одном пути, вынесено в план 24-02 (волна 2): формы заглушки index, tile, bar, block; блок CSS `access-levels` и его закрепление в `lib/style-tokens.test.ts`; тесты исходников компонентов `lib/level-ui.test.ts`; полная таблица `requiredLevelOf` в `lib/access-levels.test.ts`; граничные тесты `lib/level-placeholders.test.ts`. Решения о форме ответа (Claude's discretion в рамках D-09, записано здесь для всех планов фазы):
- Закрытое **опускается** из массивов `PortiaContent` (как ARCHITECTURE §3.4), а место заглушки передаётся отдельным маркером `content.redaction` — `{ level, slots, viruses, recycle, infoSections, infoSubsections, guideSections, guideCards, apps }`. Узел заглушки — `{ slot, requiredLevel, at }`, где `at` — индекс в полном списке. Так поиск, рекомендации и автовыбор работают только с открытым без правок, а D-08 (заглушка на месте) выполняется слиянием на клиенте. Маркер `redaction` есть в каждом ответе посетителю и никогда — в ответе редактору; по нему редактор и PUT узнают копию «для зрителя» (LVL-08, планы 24-06 и 24-08).
- `slots` — `{ id открытой записи → slot }`, чтобы клиент узнал, что открытая у него запись стала заглушкой (D-20, план 24-09). `slot` — HMAC от id с секретом сессии (`accessSessionSecret()`), id не раскрывает.
- Открытый режим закрытия (`decision.mode === "open"`, PATTERNS открытый вопрос 3): уровень = уровень одобренной заявки устройства, иначе 1. Сайт «как раньше» для всего, у чего нет `level`.
- Имена модулей: `lib/level-*.ts`, а не `lib/access-*.ts`. Причина: `lib/access-foundation.test.ts` («visitor behaviour is unchanged») запрещает `components/portia-editor.tsx` импортировать `@/lib/access-*` и всем компонентам вне списка — `access-levels`; модули уровней содержимого — отдельная область, не модули личности посетителя. `lib/access-viewer.ts` остаётся в области доступа: его используют только маршрут и `components/portia-access-gate.tsx` (оба в списке разрешённых).
- Миграции нет: уровни живут в JSON контента (D-03), очистка в TypeScript (D-04). Задача применения миграции и [BLOCKING]-шаг не нужны. Ревью `supabase-rls-reviewer` всё равно будет (план 24-11): меняется маршрут из «Охвата файлов» матрицы.

Красное окно матрицы. `app/api/content/route.ts` и `lib/access-levels.ts` входят в «Охват файлов» `23-SECURITY-MATRIX.md`, поэтому после коммита этого плана тест `lib/security-matrix.test.ts` «matrix freshness: the real matrix commit…» красный до плана 24-11 (новая матрица и ревью).
