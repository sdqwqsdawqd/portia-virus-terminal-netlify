# 24 - Браузерные доказательства (backstop, подмена всех /api/**)

Дата: 2026-11-15. Спецификация: `tests/e2e/specs/access-levels.spec.ts`. Проект Playwright: `chromium-desktop` (Chromium; размеры окна задаются в тесте: 320, 390, 900, 1440 px). Node: 22.13.1.

Как это устроено. Перед каждым тестом `page.route("**/api/**", ...)` отвечает на известные пути подготовленным JSON, а любой другой запрос к собственному `/api/**` прерывает (`route.abort`). Ответы `/api/content` строит тот же серверный код, что и настоящий маршрут (`contentBodyFor`, `slotKeyFactory` из `lib/content-response.ts`), поверх выдуманных записей без ников, ссылок и ключей. Ни один запрос не дошёл до источника данных: последний тест спецификации фиксирует, что неизвестных путей `/api/**` не было (`aborted` пуст). Файлы `.env*` агентом не читались; из окружения сервера убраны переменные live/staging-админа.

Команда сервера. `npm run build` / `npm run start` и `npx playwright` под временным Node 22.13.1 не запускаются (сломан `npm`: `Cannot find module 'node-gyp/bin/node-gyp.js'`), поэтому `webServer` конфигурации не стартовал. Сборка и сервер запущены напрямую тем же Next (`node .../next/dist/bin/next build`, затем `next start --hostname 127.0.0.1 --port 3000`, `PORTIA_E2E_ALLOW_HTTP=1`), Playwright запущен прямым вызовом CLI с `PORTIA_E2E_BASE_URL=http://127.0.0.1:3000`. Preflight (`scripts/phase15-e2e-preflight.mjs visitor`) отработал штатно: `[PORTIA_E2E_PREFLIGHT:ready] visitor`. Preflight не обходился.

## Что именно проверено

- Подменялись только ответы собственных `/api/**`; код страницы, стили и сборка настоящие.
- Закрытые записи в подготовленном содержимом получены настоящей очисткой (`redactContentForViewer`), а не написаны вручную.
- Первый прогон показал две ошибки самой спецификации (одноразовое уведомление «Доступ подтверждён» перекрывало значки на узком экране; свёрнутые разделы «Справочника» не раскрывались), они исправлены в спецификации. Продуктовый код не менялся.
