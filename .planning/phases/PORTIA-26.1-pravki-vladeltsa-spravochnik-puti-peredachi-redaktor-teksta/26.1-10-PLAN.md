<objective>
LIVE-01..05 — каркас живого редактирования и «Справочник» насквозь. Живой режим: во вкладке «Редактор» кнопка включает настоящий вид приложения участника на данных черновика, правки делаются на месте, недостающие действия — компактной панелью «Добавить: …», работает только в этом режиме.

Архитектура (одна на все приложения, планы 26.1-11…13 только добавляют приложения):
- `lib/live-edit.ts` — чистая модель: цели правки, контейнеры добавления, списки порядка и функции `applyLive*` над черновиком (поверх `lib/editor-items.ts`).
- `components/portia-live-edit.tsx` — общий модуль (вне семейств): только `LiveEditContext`, тип `LiveEditApi` (функции-отрисовщики `text`, `rich`, `image`, `addBar`, `order`, `remove`) и `useLiveEdit(app)`. Компоненты участника читают контекст и, если он есть, рисуют живые места; без контекста — прежняя разметка. Код инструментов в бандл участника не попадает: его реализует шов редактора.
- `components/portia-editor-live.tsx` — шов редактора: кнопка режима, `LiveSurface` (рисует компонент участника внутри провайдера), реализация API через мост редактора.
- `components/portia-editor.tsx` — одна вставка реестра: хук режима, кнопка в панели действий, переключение тела вкладки на `LiveSurface` и мост.

Трассер — название раздела «Справочника» насквозь: кнопка → `LiveSurface` → `GuideApp` с контекстом → правка названия на месте → черновик → «Сохранить» видит изменение → тест. Затем все виды правок справочника и панель «Добавить»; затем порядок, удаление и проверки LIVE-03/04.

Purpose: решение владельца 3 — живое редактирование в этой фазе и для всех приложений; этот план даёт каркас и первое приложение.
Output: lib-модель (+тест), общий контекст, шов живого режима, живые места в `GuideApp`, вставка реестра, CSS, тесты.
Запасной вариант по бюджету контекста (проверка планов 2026-11-20): если качество исполнения падает или контекст близок к пределу, исполнитель делит этот план по приложениям (одна задача — один план-продолжение с тем же порядком «трассер первым» и теми же проверками) и записывает разделение в SUMMARY как отклонение; объём требований при этом не сокращается.
</objective>
