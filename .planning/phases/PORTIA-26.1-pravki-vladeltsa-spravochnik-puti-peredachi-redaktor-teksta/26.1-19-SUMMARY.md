# Phase 26.1 Plan 19: живой «Доступ» как его видит посетитель, итоговая граница режима Summary

**Во вкладке «Доступ» есть кнопка «ЖИВОЙ РЕЖИМ»: она показывает экраны ворот посетителя (проверка, форма заявки, ошибка формы, ожидание, одобрено, отклонено, отозвано, ошибка связи) теми же разметкой и классами, что видит посетитель, без запросов к серверу; граница режима итоговая - живой режим у восьми вкладок, без него только «Поиск», «Сотрудники», «Пользователи».**

## Решение checkpoint

Владелец ответил заранее (2026-11-21, пункт 25 в `26.1-OWNER-REQUEST.md`): **вариант A**. Экраны ворот - код сайта; черновик контента посетителю до входа не отдаётся (SEC-01), поэтому правка их текстов на месте потребовала бы нового анонимно читаемого поля контента. План выполнен в варианте A: просмотр во всех состояниях, тексты не правятся, на поверхности одна строка «Тексты экранов — часть сайта». Вариант B не начат.

## Что сделано

Трассер (Task 1): кнопка во вкладке -> `AccessGateScreen` в состоянии «форма заявки» -> тесты. Затем (Task 2) все состояния и итоговая граница.

- **LIVE-01.** `AccessLiveTab` в шве живого режима: своя кнопка (`LiveModeToggle`), менеджер аккаунтов в `<div hidden={on}>` (остаётся смонтированным), при включённом режиме - `div.live-surface.access-live[data-live-app="access"]`. Одна вставка в редактор: `{tab === "access" && canManageEditors && <AccessLiveTab manager={<EditorAccessManager />} />}` и имя в строке импорта шва.
- **LIVE-02.** `accessPreviewStates` - восемь образцовых состояний; каждое - допустимый вход `accessGateLayout` (тест перебирает все и проверяет, какой экран выходит). Поверхность: строка вкладок состояний (`role="tablist"`, стрелки влево/вправо, `aria-selected`), под ней одна строка «Тексты экранов — часть сайта» (4 слова), затем карточка в рамке просмотра. В форме можно набирать ник и выбирать «Кем вы являетесь» (значения живут только в просмотре); кнопка отправки неактивна, под ней «Просмотр: заявка не отправляется».
- **LIVE-04.** `PortiaAccessGate` рисует карточку через `AccessGateScreen` - чистый перенос разметки; запросы `/api/access/status` и `/api/access/request`, чистка кешей устройства, уведомление остались в воротах. Без живого контекста идентификаторы и разметка прежние (в просмотре id получают префикс `access-preview-`, чтобы не встречаться с id ворот). В `AccessLiveTab` и в экране нет `fetch(`, `localStorage`, `sessionStorage` (исходная проверка, T-26.1-46).
- **Граница режима.** `LIVE_TABS` = guide, info, broadcasts, viruses, recycle, assistant, promo, access; `LIVE_EXCLUDED` = search, employees (решение 2026-11-20), users («решение владельца 2026-11-21: без живого режима»). Тесты границы обновлены с комментарием «owner 2026-11-21, item 13».
- **Охрана D-21.** Запись 24 реестра `PORTIA-26.1-LIVE-ACCESS` в `lib/format-launch.test.ts` (`applyLiveAccessHunk`: две замены, одна на файл каждая), отрицательная проверка (файл без вставки отличается, повторное применение падает, образец ожидаемого редактора содержит `<AccessLiveTab manager={<EditorAccessManager />} />`). `SAMPLE_COMMIT` не менялся. Новых русских строк в редакторе нет (D-58).
- **CSS.** Блок `.access-live-*` / `.access-gate-live` стоит перед `users-tab`, шрифты от 11px, рамка ворот `.access-gate` не менялась (охранный тест).

## Для владельца (текстом)

Редактор -> «Доступ» -> «Живой режим». Вы увидите то, что видит посетитель, подающий заявку: переключатель сверху - «Проверка», «Форма», «Ошибка формы», «Ожидание», «Одобрено», «Отклонено», «Отозвано», «Ошибка связи». Заявка не отправляется, на сервер ничего не уходит, хранилище устройства не трогается. Выключите режим - менеджер аккаунтов редакторов на месте, с тем, что вы в нём набрали.

**Что видно:** все экраны ворот в их состояниях. **Что правится:** ничего - тексты экранов часть кода сайта (вариант A). **Живой режим есть у восьми вкладок:** «Справочник», «Информация», «Сводка», «База вирусов», «Корзина», «Вивьян», «Повышение», «Доступ». **Без него три:** «Поиск», «Сотрудники», «Пользователи».

Отдельно: в «Одобрено» показана карточка со статусом, а всплывающее уведомление «Доступ подтверждён» (оно закреплено в углу окна и принадлежит воротам) в просмотр не входит.
