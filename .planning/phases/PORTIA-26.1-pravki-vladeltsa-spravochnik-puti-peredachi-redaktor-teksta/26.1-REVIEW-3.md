```ts
const panelId = await dropdown.getAttribute("aria-controls");
```

Ещё стоит добавить e2e-проверку, что панель открывается в `body` и не меняет `scrollHeight` формы. Именно на это жаловался владелец в п. 32.

### WR-01: проверка при загрузке навсегда переписывает места ярлыков, если окно ПК меньше прежнего

**File:** `components/portia-desktop.tsx:1016-1038`; `lib/shortcut-layout.ts:301-303`, `:346-367`
**Issue:** Один раз за загрузку эффект вызывает `resolveShortcutOverlaps(current, …, grid, gridOn)`. Тот сначала зажимает каждое сохранённое место в текущую площадь (`insideGrid`), и если что-то сдвинулось, результат пишется в `portia-desktop-shortcuts-v3`. Коммит ba724d34 закрыл только узкие окна (≤900px). Любое окно ПК меньше того, где раскладывали ярлыки, переписывает их так же: половина экрана при 960px, ноутбук после большого монитора, открытые справа devtools. «Корзина», сохранённая у правого края 1920px, после одного открытия на 1366px навсегда остаётся у 1264px. На большом экране раскладка не возвращается. Раньше зажим был только визуальным (`savedShortcutLayout`, CSS `min(...)`), и там прямо сказано: «a position saved on a bigger screen is held inside the desktop so the icon never disappears». Хук `useShortcutPlacement` и сейчас зажимает места только для показа, без записи. Разрушительна именно запись. 26.1-23-SUMMARY.md:156 называет это ограничение, но исправлено оно только для узких окон.
**Fix:** при загрузке переписывать только места, которые накладываются в своих сохранённых координатах. Зажим в площадь оставить показу:

```ts
const outside = desktopShortcutOrder.some((id) => { const p = current[id]; return p && (p.x + cell.width > grid.area.width - 8 || p.y + cell.height > grid.area.height - 8); });
if (outside) { shortcutOverlapsChecked.current = true; return; } // меньшее окно: показ зажимает сам, ключ не трогаем
```
Другой вариант: дать `resolveShortcutOverlaps` флаг `clamp: false` для этого вызова.

### WR-03: верхняя панель смешивает visual viewport и layout viewport и при зуме или клавиатуре съезжает на кнопку

**File:** `components/portia-editor-dossier.tsx:411-413`, `:416-418`; `lib/route-dropdown-position.ts:32-41`
**Issue:** `routeViewport()` берёт `visualViewport.height` и `visualViewport.width`. Прямоугольник кнопки (`getBoundingClientRect`) и `position: fixed` при этом считаются от layout viewport. Для верхней панели пишется `bottom = viewport.height - anchor.top + gap`. CSS `bottom` отсчитывается от низа layout viewport. При щипковом зуме на телефоне или открытой клавиатуре iOS visual viewport меньше layout. Тогда нижний край панели оказывается на `anchor.top - gap + (layoutH - visualH)` и закрывает кнопку на эту разницу. Горизонтальный зажим `left` тоже идёт по ширине visual viewport без `offsetLeft`. Старая версия была привязана к кнопке через CSS (`bottom: calc(100% + 4px)`) и такой ошибки не имела. Довод «верхняя панель висит на нижнем крае, чтобы длинное описание росло вверх» устарел: подвал теперь фиксированной высоты (`.route-dropdown-foot { height: 8.4em }`), и высота панели при наведении не меняется.
**Fix:** размеры для координат брать от layout viewport, для обеих сторон писать `top`:
```ts
function routeViewport() { return { width: document.documentElement.clientWidth, height: document.documentElement.clientHeight }; }
// writeRoutePanelPlace: node.style.top = `${place.top}px`; node.style.bottom = "auto";
```
Если нужен учёт клавиатуры, ограничивать `maxHeight` пересечением с `visualViewport.offsetTop + height`.

### WR-04: многострочные поля живого режима без `field-sizing` сжимаются до одной строки

**File:** `components/portia-editor-live.tsx:684`, `:718`; `app/portia.css:2962`, `:3053`
**Issue:** Нижнюю границу строк убрали (`Math.max(3, …)` и `Math.max(2, …)`), теперь `rows = число переводов строки + 1`. Высоту по тексту даёт только `field-sizing: content`, а этого свойства нет в браузерах вне Chromium (например, в Firefox). Комментарий в CSS это признаёт: «без него — строки по числу абзацев». Правила квалификации, текст задания и условия квеста обычно один длинный абзац. В таком браузере это поле высотой в одну строку с внутренней прокруткой, и править длинный текст приходится вслепую. Тест `live-inline.test.ts:127-128` закрепляет именно эту формулу.
**Fix:** держать запасной вариант в CSS и не трогать `rows`:
```css
@supports not (field-sizing: content) {
  .promo-live textarea.live-textarea, .live-surface .broadcast-conditions .live-textarea { min-height: 4.8em; }
}
```
Можно и мерить `scrollHeight` при вводе (`element.style.height = element.scrollHeight + "px"`).

**File:** `lib/shortcut-layout.ts:206-209`, `:361-364`; `components/portia-desktop-shortcuts.tsx:121`
**Issue:** Когда клеток меньше двенадцати, `homeShortcutPositions` и `resolveShortcutOverlaps` ставят ярлык в ряд под площадью. На планшете это прокручиваемый `contentHeight`. На ПК `contentHeight = area.height`, а `.workspace` обрезан. Так бывает при высоте окна ПК меньше примерно 300px: тогда `rows = 1` и `columns` около 8–9. Ярлык исчезает, и до него не дотянуться ни мышью, ни Alt+стрелкой (`gridCellIndex` зажимает ряд). Раньше CSS-зажим `savedShortcutLayout` гарантировал, что «the icon never disappears».
**Fix:** на ПК при нехватке клеток уменьшать шаг или класть лишние ярлыки поверх последнего ряда со сдвигом. Либо отдавать `contentHeight` больше площади и разрешать прокрутку `.desktop-icons` (`overflow-y: auto`) только в этом случае.
