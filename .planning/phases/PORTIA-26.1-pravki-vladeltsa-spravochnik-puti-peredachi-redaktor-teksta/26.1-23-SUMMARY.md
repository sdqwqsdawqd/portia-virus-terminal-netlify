# Phase 26.1 Plan 23: ровная сетка ярлыков до панели задач, исходные места на сетке, ярлыки не накладываются — Summary

**Одна ровная сетка `desktopGrid` на всю площадь рабочего стола до панели задач, двенадцать исходных мест в её клетках (`homeShortcutPositions`) и правило «ярлык никогда не ложится на другой» (`placeShortcutDrop`, `resolveShortcutOverlaps`) — на ПК и на 521–900px.**

## Для владельца

Сетка ровная до панели задач, нижний ряд доступен; исходные места — на сетке; ярлыки никогда не ложатся друг на друга.

- **Пункт 31:** сетка теперь считается из всей ширины и высоты рабочего стола: сколько клеток помещается, а остаток делится поровну между ними. Нижний ряд кончается у верхнего края панели задач, ярлык можно поставить туда и перетаскиванием, и Alt+стрелкой. На 521–900px область ярлыков тоже доходит до панели задач (раньше снизу отрезалось около 40px).
- **Пункт 29:** все ярлыки, включая «Устав», «Таблицу» и «Корзину», стоят в клетках сетки: два столбца слева сверху, «Устав» и «Таблица» в нижнем ряду, «Корзина» в правом верхнем углу. «Выровнять ярлыки по сетке» их не сдвигает, «Вернуть ярлыки в изначальное положение» ставит все в эти клетки.
- **Пункт 30:** если бросить ярлык на другой, он встаёт на ближайшее свободное место (с сеткой — в ближайшую свободную клетку, без сетки — на ближайшее место, где он ни с кем не пересекается). То же для Alt+стрелок. Если ярлыки уже лежали друг на друге в сохранённой раскладке, при загрузке они разъезжаются на свободные места. Чтение экрана говорит «Место занято — ярлык рядом».
- Расположение на экране я не проверял глазами: проверка на 1366/1920 и в окне 700px остаётся за вами (см. ниже, BLOCKED).

## Accomplishments

- `desktopGrid(area, cell, inset = 8)` → `{ columns, rows, pitchX, pitchY, originX, originY, cell, area }`; `gridCellPosition(grid, column, row)` — ярлык по центру клетки. Все функции сетки (`snapShortcutPosition`, `nearestFreeGridCell`, `freeGridCellAlong`, `alignShortcutsToGrid`) переведены на этот объект — одна сетка на всё.
- `homeShortcutCells` (отрицательный индекс — от правого/нижнего края) и `homeShortcutPositions(grid)` — двенадцать мест, каждое на клетке, без совпадений, при нехватке строк — переход в следующий столбец, при нехватке клеток — ряды ниже области.
- ПК: `useShortcutPlacement` измеряет стол и ставит ярлыки без сохранённого места в их клетки; сохранённые места выбирают первыми, наложения разводятся `resolveShortcutOverlaps`.
- `placeShortcutDrop(id, point, positions, cell, grid, gridOn, obstacles?)` → `{ position, displaced }`; `nearestFreeShortcutSpot` — перебор по решётке 8px внутри области, ближайшее свободное место.
- `resolveShortcutOverlaps(positions, order, cell, grid, gridOn?)` — зажим в область, перенос пересекающихся, места без пересечений не меняются; рабочий стол вызывает его один раз после загрузки и пишет в `portia-desktop-shortcuts-v3` только если что-то сдвинулось.
- `placeShortcuts` (521–900px) заполняет клетки той же сетки; запас 56px остался только как запас прокрутки под выросшим содержимым; `shortcutDropArea` удалён.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The CSS clamp of a saved place kept shortcuts out of the bottom row**
- **Found during:** Task 1
- **Issue:** `savedShortcutLayout` clamps `top` to `calc(100% - 128px)` (the room for the large size). For the standard size that is about 13px above the bottom row of the new grid, so a shortcut could not stand in the bottom row and the bottom-row homes would have been pushed off the grid.
- **Fix:** on the PC the shortcuts now use the JS placement (`placedShortcutLayout`, already clamped exactly to the cell size). The CSS clamp is kept only for the frame before the first measurement. The test string of the clamp is unchanged.
- **Files modified:** components/portia-desktop-shortcuts.tsx
- **Commit:** a6a70ad4

**2. [Rule 1 - Bug] While dragging, the saved places changed on every pointer move**
- **Found during:** Task 2
- **Issue:** with the no-overlap rule in the placement, the dragged shortcut (as a saved one) would have pushed the shortcuts under it aside while it was still being dragged.
- **Fix:** the drag is drawn by the dragged shortcut only (`dragPosition`), and `onMove` runs once, on the drop.
- **Files modified:** components/portia-desktop-shortcuts.tsx
- **Commit:** bf92365b

**3. [Rule 3 - Blocking] `react-hooks/set-state-in-effect` on the load-time check**
- **Found during:** Task 2
- **Fix:** like the other restore effects of the desktop, the write goes through `setTimeout(0)` with a functional update (pure, Strict Mode replays it safely) and a cleanup.
- **Commit:** bf92365b

### Other notes on the plan wording

- With the grid on, Alt+Arrow stays on `freeGridCellAlong` (the jump over taken cells from WR-05), not on `placeShortcutDrop`. It already never lands on a taken cell. Without the grid, Alt+Arrow goes through `placeShortcutDrop`.
- `placeShortcutDrop` and `resolveShortcutOverlaps` take an extra optional argument each (`obstacles` and `gridOn`), so the assistant and the format button stay free and a saved place with the grid on is moved to a cell.
- `placeShortcuts` lost its `gap` argument (one grid, no separate step) and got `gridOn`; it returns `grid` too. `shortcutDropArea` was removed because nothing uses it any more.
- In the UI-09 test "the content grows downwards", the area was lowered from 521×400 to 521×300. With the denser grid, 521×400 now fits all eleven shortcuts, so it no longer exercises the growth.
