# Phase 26.1 Plan 17: банки - предел тела, честные 403 и 503 (L1-L3) Summary

**Маршрут `POST /api/promotion/banks` ограничивает тело 64 КиБ до разбора JSON для любого действия, ограничивает `manualIds` (до 100 id по 64 знака) и `replaceId` (до 64 знаков), отвечает 403 на отказ прав при синхронизации счётчиков и понятным 503 `pending-config` при отсутствующем или коротком ключе превью.**

## Что сделано

Трассер (Task 1, L1): чистая функция предела -> маршрут проверяет размер текста до `parseJsonObject` -> большое тело preview/confirm получает 413 -> тесты. Затем `manualIds`, L2 и L3 (Task 2).

Три пункта ревью и что изменилось в ответах:

- **L1.** Раньше предел проверялся только после ветки preview/confirm (`JSON.stringify(body).length`), то есть preview и confirm разбирали тело любого размера. Теперь `bankBodyTooLarge(text)` стоит сразу после `requirePromotionReviewer` и до `parseJsonObject`; ответ 413 «Данные слишком велики.» для всех действий. Прежняя поздняя проверка удалена. `manualIds` - не массив, длиннее 100, элемент не строка или длиннее 64 знаков -> 400 `{ code: "invalid-selection" }`; `replaceId` длиннее 64 -> тот же 400. Отсутствующий `manualIds` ведёт себя как раньше (случайный набор); клиент поле без значения не шлёт.
- **L2.** Отказ `forbidden` (или SQLSTATE 42501) RPC `portia_promo_bank_command` при синхронизации счётчиков перед подтверждением раньше давал 409 «Банк изменился. Соберите набор заново.»; теперь `denied("forbidden")` - 403 «Вкладка «Повышение» для вас закрыта.». Прочие ошибки синхронизации (`42883` -> 503 pending-database, остальные -> 409 stale) прежние.
- **L3.** `promotionDeviceSecret()` бросает при ключе короче 32 знаков, и маршрут отвечал необработанным 500. Теперь `previewSecretOrNull` даёт `null`, и preview и confirm отвечают 503 `{ error: "Сборка набора временно недоступна.", code: "pending-config" }` с `noStoreHeaders`. Права проверяются первым шагом (403 без ключа не раскрывает, настроен ли он), проверка стоит после поиска банка (404 раньше).

SQL, миграции и проверка прав не менялись; первым шагом остаётся `requirePromotionReviewer`.

## Для владельца (текстом)

Видимого изменения в окне нет. Если запрос банков слишком большой, сервер отвечает «Данные слишком велики.» ещё до разбора. Если у проверяющего отозвали вкладку «Повышение» между предпросмотром и подтверждением, он увидит «Вкладка «Повышение» для вас закрыта.», а не «Банк изменился». Если на сервере не задан ключ предпросмотра, сборка набора отвечает «Сборка набора временно недоступна.» вместо сбоя.
