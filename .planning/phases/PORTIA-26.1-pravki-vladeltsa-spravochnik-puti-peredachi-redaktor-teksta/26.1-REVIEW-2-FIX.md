## Fixed Issues

### CR-01: Escape в многострочном `LiveCommitText` сохраняет правку вместо отмены

**Files modified:** `components/portia-editor-live.tsx`, `lib/live-edit.ts`, `lib/live-edit.test.ts`
**Commit:** 4229fea7
**Status:** fixed: requires human verification
**Applied fix:** решение «записывать или нет» вынесено в чистую `liveCommitDecision({ raw, saved, cancelled })`. Escape выставляет ref-флаг `cancelled` до `blur()`, `commit()` читает и сбрасывает флаг, поэтому blur внутри того же keydown больше не отправляет набранный текст. Один механизм для `textarea` и однострочного `span`. Добавлен поведенческий тест на чистую функцию (отмена при любом набранном тексте, обычный blur, равный текст с точностью до краёв, очищенный текст).

### CR-02: вторая команда живого «Повышения» молча выбрасывается

**Files modified:** `components/portia-promotion-editor-main.tsx`, `lib/live-edit.ts`, `lib/live-edit.test.ts`
**Commit:** 85489929
**Status:** fixed: requires human verification
**Applied fix:** флаг `savingRef` заменён последовательной очередью `createLiveCommandQueue` (чистая, в `lib/live-edit.ts`). Команды ставятся в очередь, а не отбрасываются; каждая собирается, когда до неё дошёл черёд, из банков, которые оставила предыдущая команда (`latestBanksRef`), так что две правки одного вопроса не затирают друг друга. Список команд (перестановка) отправляет `runLivePayloads`, он останавливается на первом отказе. Строка состояния честная: «Сохраняю…» пока что-то ждёт, сообщение об успехе только когда прошли все, первый отказ остаётся до следующей серии. Перестановка с отказом показывает ошибку, а не откатывается молча (пустой список команд не создаёт сообщений). Кнопки строк («Выключить», «×», «Ответ…», добавление) больше не отключаются по `busy`, иначе blur-then-click терял клик; диалог «Ответ…» по-прежнему получает `busy`. Тесты: порядок и сериализация очереди, отказ не блокирует следующую задачу, `pending`, остановка списка команд на отказе, ответ без `state` не считается сохранением. Старая проверка исходника `/savingRef/` в `lib/live-edit.test.ts` заменена на проверку очереди.
**Известное ограничение:** два очень быстрых нажатия «добавить вопрос» в переходе без банка поставят в очередь два `save-qualification-bank`; сервер должен принять повтор (не проверялось, без доступа к БД).

### WR-01: при отказе сервера набранный в живом режиме текст теряется

**Files modified:** `components/portia-editor-live.tsx`, `components/portia-promotion-editor-main.tsx`, `lib/live-edit.ts`, `lib/live-edit.test.ts`
**Commit:** 83fc5306
**Status:** fixed: requires human verification
**Applied fix:** `onCommit` теперь возвращает `Promise<boolean | void>`; `false` или исключение означает отказ. При отказе набранный текст остаётся в поле (`typed` не сбрасывается, слой синхронизации не перезаписывает `span`), поле помечается `aria-invalid`; повторный blur повторяет команду, Escape снимает правку. `commitText` возвращает признак успеха. В живом режиме баннер конфликта говорит «Данные изменились. Текст остался в поле.» (текст в `liveCopy.promo.conflictKept`, не длиннее шести слов из-за реестра D-56); в обычном режиме прежнее «Ваш ввод сохранён.». Чистая `liveCommitSucceeded` покрыта тестом.

### WR-02: включение живого режима «Повышения» размонтирует обычные редакторы

### WR-04: кэш снимков окон `lastPreviewClone` переживает смену зрителя

**Files modified:** `components/portia-desktop-taskbar.tsx`, `components/portia-desktop.tsx`, `lib/portia-desktop.test.ts`
**Commit:** c0b9782b
**Status:** fixed: requires human verification
**Applied fix:** снимок берётся в `requestExit` в момент сворачивания (`rememberWindowPicture(appId)`, окно ещё на экране), при закрытии окна удаляется (`forgetWindowPicture`), а эффект `PortiaDesktop` по `[viewerKey, viewerPerson]` вызывает `forgetWindowPictures()` при смене зрителя или человека и при размонтировании. Запись снимка при закрытии превью убрана (он мог быть часовой давности). Карта осталась модульной (по условию «ключ по зрителю» достаточно очистки при смене). Тесты структурные.

### WR-05: «Выровнять значки по сетке» допускает два ярлыка в одной клетке

**Files modified:** `components/portia-desktop-shortcuts.tsx`, `lib/shortcut-layout.ts`, `lib/shortcut-layout.test.ts`
**Commit:** fdfd8cc9
**Status:** fixed: requires human verification
**Applied fix:** две чистые функции в `lib/shortcut-layout.ts`. `nearestFreeGridCell` выбирает ближайшую клетку сетки, не занятую ни другими ярлыками, ни препятствиями (при равенстве верхняя строка, затем левый столбец); результат всегда клетка сетки, поэтому последующий clamp, сдвигавший ярлык с сетки, больше не нужен. `freeGridCellAlong` для Alt+стрелки перепрыгивает занятую клетку в том же направлении, у края останавливается на последней свободной, без свободной клетки возвращает `null`: ярлык остаётся и объявляется «Ярлык «…» остался на месте: клетка занята». Прямоугольники соседей берутся из DOM (`[data-shortcut]`). Если свободных клеток нет вовсе, остаётся прежний путь snap + clamp. Тесты на обе функции (свободная, занятая, препятствие, нет свободных, NaN, край, шаг в 4 клетки).
