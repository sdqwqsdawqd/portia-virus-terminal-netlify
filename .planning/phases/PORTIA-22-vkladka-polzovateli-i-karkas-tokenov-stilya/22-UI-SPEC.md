## Layout and Interaction Contract

### Tab shell

- Registry line placed **after «Сотрудники», before «Повышение»**; `EditorTab` union gains `"users"`. The tab is not a content section: no draft, no save chip, no undo history. Add `"users"` to the `historyTab` exclusion beside `employees | promo | access` so `Ctrl+Z/Y` stay native.
- Pending badge: `<span class="tab-count" aria-hidden="true">N</span>` after the label; button `aria-label="Пользователи, ожидают: N"`. Hidden at 0 and while the count is unknown or failed (never show a stale number). Shows `99+` above 99. Style: 11px 700 mono (`var(--mono)`), `var(--warning)` text, `1px solid var(--warning)` border, padding `0 8px`, `min-width: 24px`, `margin-left: 8px`, no radius.
- Count freshness: fetched on editor mount, on tab activation, after every decision, then every 30 s while the editor window is visible and `document.visibilityState === "visible"`. It counts pending requests only (D-01) and must equal the total in the «ЗАЯВКИ · N» title without a search filter (the total, not the up-to-50 rows shown).
- If the owner closed the tab for this editor, it is absent from the strip (registry mechanics). If the server answers 403 for a body that is already mounted, the body renders `AppDeniedPanel` only (`Доступ закрыт`, `role="alert"`, no buttons).

### Body structure (PC and phone, top to bottom)

Visual anchor (one per screen): on PC the «ЗАЯВКИ» section and its first row (the only place with a `.primary-control` and warning plaques); on phone the pending list at the top plus the warning count on the tab. Nothing else competes: «ЛЮДИ» and the closed block are neutral.

1. Live region `role="status" aria-live="polite"` (action results, bulk summary). Errors use `role="alert"`.
2. `AppStaleBanner` when a refresh failed but data is on screen.
3. Search: `.editor-field` with visible label «ПОИСК ПО НИКУ», `type="search"`, `maxLength=20`, `autocomplete="off"`, `autocapitalize="off"`, `spellcheck="false"`, placeholder «Начните вводить ник». One field filters both sections and the collapsed block (D-02). Match = substring on `nicknameKey` (case-insensitive) of both sides; server-side over all rows (the 50-row display cap must not hide a match), debounced. No status filters.
4. Section «ЗАЯВКИ · N» (`<section aria-labelledby>`, title `tabIndex=-1`). Owner only: button `ОДОБРИТЬ ИЗ ТАБЛИЦЫ` right-aligned in the section header (wraps under the title at ≤900px). Rows sorted oldest request first.
5. Section «ЛЮДИ · N»: approved people, level descending then nickname ascending (D-03). One caption under the title: «Время указано по Москве (МСК).»
6. `<details>` «Отклонённые и отозванные · N», closed by default; `summary` min-height 44px on phone. Rows sorted by latest decision first.

Editors never see the bulk button, `СНЯТЬ ПАУЗУ`, or full emails: those elements are **absent**, not disabled. Actions the database forbids are absent too (see "Server-driven permissions").

- Tap opens the **action window**: native `<dialog>` on `.portia-dialog` chrome, modal, width `min(420px, calc(100vw - 24px))` (existing), `max-height: calc(100svh - 24px)` with the body scrolling inside (`overflow-y: auto; overscroll-behavior: contain`). Sections in order: title (nickname, Heading) · `dl` «ТИП», «В ТАБЛИЦЕ», «ПРОФИЛЬ» (the link) · caption of the last decision · level `select` (16px) · action buttons stacked full width, 44px · «ИСТОРИЯ» list (same entries as PC, always expanded) · `ЗАКРЫТЬ ОКНО` (secondary, last). - `ОТКЛОНИТЬ` / `ОТОЗВАТЬ` in the window: close the window, then open the confirmation (one modal at a time); cancel returns focus to the row.

### Decisions (Claude's Discretion made concrete)

| Action | Confirmation | Notes |
|--------|--------------|-------|
| Approve (single) | none | Level from the select; reversible by revoke |
| Change level | none | Sends `expectedLevel`; `stale` → note «Уровень уже изменили. Показан актуальный.» and refresh the row |
| Reject | `ConfirmDialog`, safe action autofocused | No reason field |
| Revoke | `ConfirmDialog`, safe action autofocused | No reason field; text states the old level is not restored |
| Clear cooldown (owner) | none | Note «Пауза снята» |
| Bulk approve (owner) | bulk dialog (below) | USR-08 |

Row feedback: while a request is in flight, the row has `aria-busy="true"`, its controls are disabled and the pressed button shows the busy label (`ОДОБРЯЕМ…`, `ОТКЛОНЯЕМ…`, `СОХРАНЯЕМ…`, `ОТЗЫВАЕМ…`). A refusal appears as a `role="status"` note directly under the row (text colour per Color), then that row is refetched. **«Уже решено» (USR-07)** is a refusal note on the row followed by the refresh; the row then lands in its true section. Result-code mapping: `already-decided` → «Уже решено. Строка обновлена.»; `not-found` → «Заявка не найдена. Список обновлён.»; `not-active` → «Человек уже не активен. Список обновлён.»; `stale` → see above; any `AccessStoreError`/network/`unexpected-reply` → «Не удалось выполнить. Проверьте связь и повторите.» (the button is enabled again; nothing is retried automatically).

Focus after a row leaves its section: move to the next row's first control in the same section, else to that section's title (`tabIndex=-1`). Never leave focus on `<body>`.

### Server-driven permissions

The list payload carries per-row permission flags (planner names them; the UI never infers). A row whose flag is false shows no control for that action and one caption instead: self → «Свою заявку решить нельзя.»; owner → «Владельца изменить нельзя.». The level `select` offers levels `1..callerLevel`. The UI is a convenience; the database remains the enforcer (USR-05, Phase 21).

### Masked deciders and time (D-05, D-06)

- Decider text comes from the server as-is (`q•••z@gmail.com` for editors, full email for the owner). The client never builds or unmasks an email. Missing decider → «неизвестно».
- Date/time: a pure function in `lib/` (node-testable), device-independent: `Intl.DateTimeFormat("en-GB", { timeZone: "Europe/Moscow", hourCycle: "h23", ... }).formatToParts` for numbers only, with an **own** Russian month table (янв., февр., мар., апр., мая, июн., июл., авг., сент., окт., нояб., дек.). Output «9 нояб., 14:32»; the year is appended («9 нояб. 2025 г., 14:32») only when the year differs from the current Moscow year. Render inside `<time dateTime="ISO">`. Never `toLocaleString()` without a fixed zone/locale.
- Verb follows the event: одобрил, отклонил, отозвал, изменил уровень, снял паузу.

### Bulk approval dialog (D-08, D-10, D-11)

- Button `ОДОБРИТЬ ИЗ ТАБЛИЦЫ` is `disabled` (not hidden) when: roster `degraded` → caption next to it «Таблица сотрудников недоступна, попробуйте позже»; or zero eligible → caption «Нет заявок «из таблицы» с ником из таблицы.» Captions are visible text, not tooltips.
- Dialog (native `<dialog>`, `.portia-dialog` chrome, `role="alertdialog"`): title «Одобрить N заявок с уровнем 2?» (plural rule below); block 1 «Будут одобрены» = nickname list; block 2 «Не входят (ника нет в таблице)» = nicknames of «из таблицы» requests not in the roster, shown only when non-empty. Each list: `max-height: min(40svh, 320px); overflow-y: auto`, one nickname per line, `overflow-wrap: anywhere`. Up to 200 pending requests are possible (`maxPending`), so the lists scroll; the actions row stays visible.
- Actions: `ОДОБРИТЬ` (primary), `НЕ ОДОБРЯТЬ` (secondary, autofocused; same "НЕ + verb" pattern as «НЕ ОТКЛОНЯТЬ» / «НЕ ОТЗЫВАТЬ»). Nothing is approved before `ОДОБРИТЬ` (USR-08).
- Running: each request is decided separately and sequentially; buttons disabled; Esc and backdrop ignored; progress line `aria-live="polite"`: «Одобрено k из N». One failure does not stop or undo the others. On finish the dialog closes and the status region shows the summary «Одобрено X, уже решено другим Y, ошибка Z» (always all three numbers). Failed requests stay in «Заявки»; already-decided ones are refetched.
- Russian plural of «заявка» after «Одобрить N»: n mod 10 = 1 and n mod 100 ≠ 11 → «заявку»; n mod 10 in 2..4 and n mod 100 not in 12..14 → «заявки»; else «заявок». The plural helper is shared and unit-tested.

### Motion

No new animation. Rows appear/disappear without transition; dialogs use the existing native behaviour. `data-motion="off" | "reduced"` therefore needs no handling here.

## Assumptions for the planner (genuinely open; no owner available)

- **A1 shadcn gate.** `components.json` is absent and the stack is Next.js/React, which normally triggers the shadcn prompt. It was not asked or run: shadcn would conflict with "the site does not change visually" and with the existing 2,456-line stylesheet. Recorded as `Tool: none`. The owner can revisit in Phase 26.
- **A2 Tab position.** After «Сотрудники», before «Повышение». `lib/editor-tabs.test.ts` and `tests/e2e/specs/editor-ui-contract.spec.ts` iterate `tabRegistry`; both must be updated and re-read, not assumed.
- **A3 Data contract.** A new editor-session route (for example `/api/users`) calls the definer RPCs and returns, per row: id, nickname, origin, status, level, `createdAt`, table mark (`yes | no | unknown`), last event (verb, masked-or-full decider text, timestamp), `retryAt` (cooldown), and permission flags (can decide, can set level, can revoke, protected, self). History is a separate or same-call read of the last 5 entries. Field names belong to the RPC design; this spec fixes what the UI shows. The route refuses with 403 when the tab is closed for that editor. Owner vs editor comes from the existing `canManageEditors` prop.
- **A4 Polling.** List: every 10 s while the tab is active and the document is visible (as the promotion queue does); badge: 30 s. Both pause when hidden and refetch on visibility return.
- **A5 Sorting not fixed by the owner.** Requests oldest first; closed block latest decision first.
- **A6 Roblox profile URL.** `https://www.roblox.com/user.aspx?username={encodeURIComponent(nick)}`, `target="_blank" rel="noopener noreferrer"`, `aria-label="Профиль Roblox: {ник} (откроется в новой вкладке)"`. The redirect behaviour is unverified here; the executor checks the URL form before relying on it. `robloxUserId` is not used (D-09).
- **A7 Volume (resolved by owner).** Cap 50 rows per section, truncation line «Показаны первые 50. Уточните поиск.», no pagination; search is server-side over all rows; totals and bulk eligibility are computed over all rows (see UI Considerations).
- **A8 Token skeleton is declare-only** (see Shape and Style Tokens).
- **A9 Checkpoint timing.** Place it last in plan order; it blocks phase closure, not implementation. Record the answer in the phase folder.
- **A10 Test style.** The repo's component tests are `node:test` over `lib/*.test.ts` (source-text and static-markup assertions). Component tests for the tab follow that style; live Postgres/RLS, authenticated roles and devices stay BLOCKED.
- **A11 `--muted`.** Left undefined on purpose (see Design System). Phase 26 decides.
- **A12 SQL.** Any new RPC, the journal prune (D-07) and the trigger change need `supabase-rls-reviewer`, and fingerprint plus expected-authz updates in the same commit (CLAUDE.md, Phase 21). Out of scope for this UI contract beyond the payload shape in A3.
