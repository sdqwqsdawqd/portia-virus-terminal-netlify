# 20-UAT: журнал физической приёмки владельцем (PC, затем phone)

Журнал подготовлен агентом (план 20-27) и заполняется только владельцем. Проверяется `lib/phase20-uat.test.ts`; со строгим режимом `PORTIA_REQUIRE_UAT=1` проверка требует финальных статусов и двух вердиктов (план 20-14, Task 2).

## Правила

1. Порядок (D-13): сначала полный чек-лист на физическом PC после clean reload, затем полный чек-лист на физическом phone после clean reload. Таблица PC идёт раньше таблицы phone. У каждого устройства отдельный вердикт.
2. Для каждого шага записывать (D-16): статус, устройство, проверенный commit (7-40 шестнадцатеричных символов, существующий в репозитории), дату ГГГГ-ММ-ДД, короткую заметку; при отклонении (FAIL) приложить скриншот и указать его путь.
3. Статусы шага: `ОЖИДАЕТ`, `PASS`, `FAIL`, `BLOCKED (ENV)`, `BLOCKED (DATA)`, `BLOCKED (OWNER)`, `BLOCKED (DEVICE)`. `BLOCKED` остаётся `BLOCKED`: причину записать в заметку, в `PASS` не переводить. Агент не ставит `PASS` в шаги и вердикты.
4. `PASS` шага не ставится, пока prerequisite из колонки «Зависит от» не `PASS` (для `OWNER-MIG-*` — `ПРИМЕНЕНО ВЛАДЕЛЬЦЕМ` с датой). Если prerequisite не доказан, шаг получает `BLOCKED`.
5. Medium-дефект доступности и необъяснённое report-only нарушение CSP не становятся `PASS` (D-10, D-05): до вердикта владельца шаг остаётся `FAIL`.
6. Опубликованный HTTPS-сайт не проверяется, production не изменяется (D-14). Проверка идёт на изолированном staging и локальной production-сборке; доказательство по LAN (HTTP) не выдаётся за доказательство HTTPS или HSTS опубликованного сайта.
7. Если после полной приёмки исправлен только phone-дефект, владелец повторяет весь phone-чек-лист на новом commit, а PC-вердикт сохраняется с исходным commit (D-15). Оба commit, объём изменения и основание записываются в раздел «D-15» ниже; любое другое изменение требует повторной приёмки обоих устройств.
8. Вердикт устройства: `PASS (commit <hex>)` только если все шаги этого устройства `PASS`; иначе `FAIL (commit <hex>)`.
9. Prerequisite-строки `OWNER-MIG-D36` и `OWNER-MIG-NOTES` заполняет только владелец (дата и способ применения на production); агент не проверяет production и не ставит в них `PASS`.
