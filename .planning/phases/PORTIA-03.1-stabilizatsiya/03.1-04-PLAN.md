Findings at planning time (re-grep the anchors; line numbers have moved after waves 1-2):
- Boot every load. In components/portia-desktop.tsx, booting starts true (~252) and the mount effect ends it after
  1650 ms (~422) on every load. BootScreen (~1229-1245) is server-rendered visible, so a skip decided only in React would
  still flash the boot screen until hydration. The constant head script lib/accent-boot.ts already runs before first
  paint and sets html dataset values. It is tested in lib/accent-theme.test.ts through runBoot(), which runs the script
  with new Function("localStorage", "document", "matchMedia", …).
- Spider before web. In app/portia.css the spider `.boot-core > .portia-mark` (~625) runs spider-descend: translateY from
  −46vh, opacity 0 → 1 by 70%, expo-out, 900 ms. Its thread `.boot-thread` (~1205) runs a separate thread-spin
  (translateX(−50%) scaleY 0 → 1 from the top). Both are paused until `.boot-core.is-ready`. Opacity uses the expo-out
  per segment, so the spider is visible within about 100 ms. At the same eased progress p, the spider body sits at
  rest − 46vh·(1−p) while the thread tip sits at rest − 50vh·(1−p). The spider therefore falls up to 4vh (about 40 px on
  a 1080 px screen) ahead of its thread at the start. The gap depends on viewport height and image-load timing, hence
  "sometimes". The cure is structural: the thread hangs above the spider at full length and moves with it, on the same
  keyframes. Under «Выключены», `html[data-motion="reduce"] :is(.boot-core > .portia-mark, .boot-thread)` fades both in
  together (~1380). That stays.
- Assistant font. Every phrase kind renders in the same element: `.assistant-bubble > span` (heading) +
  `<FormattedText className="assistant-formatted-text">` (~1195). FormattedText's root is itself a span and a direct child
  of .assistant-bubble, so the heading rule `.assistant-bubble > span { font: 500 11px var(--sans); letter-spacing: .09em }`
  (specificity 0,1,1) beats `.assistant-formatted-text { font: 700 10px/1.5 var(--assistant-font) }` (0,1,0) on the root.
  This is the STATE.md blocker from phase 1. The run spans are pinned by
  `.assistant-formatted-text > span { font-family/size/weight !important }`. The offended rules found change only colours
  (`.desktop-assistant.is-offended .assistant-bubble span`, `… .assistant-formatted-text > span`). No offended-only font
  rule was found by reading, so the source of the owner's "different font" is not certain. Candidates: a breakpoint rule,
  the heading rule on the root, the live content of formattedText["assistant:offended"] (runs, GIF links), or
  something else in the cascade. Task 2 step 1 confirms it.
- Head-script safety rule (lib/accent-boot.ts comment): never interpolate a runtime or user value. Constants via
  JSON.stringify are fine; accentIds already works this way.
Baselines: npm test passing (85 + waves 1-2 additions); npm run lint 0 errors / 13 warnings.
