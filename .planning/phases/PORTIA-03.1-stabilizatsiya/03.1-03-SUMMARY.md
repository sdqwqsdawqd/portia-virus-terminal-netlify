# Phase 03.1 Plan 03: Wallpaper rework Summary

The wallpapers now follow D-07. With «Анимации: Выключены» every wallpaper is still and fully drawn from the first frame: the web shows all its threads and dew, and the helix, gel and cells don't move. Windows, menus and Vivian keep their soft transitions from dd26f5b. With «Включены» the DNA helices drift upward at a constant speed in a seamless 720-unit loop. This runs as a compositor `translate` of one HTML-level svg, so the clock's once-a-second re-render cannot drop its frames. The web draws in evenly without cap dots, sways by rotation only, and the glints are gone. «Гель» bands and labels stand still, are thinner and more even, and only their glow breathes slowly. Switching wallpapers crossfades (also from and to «Чистый»).

## What changed

- **Motion switch (app/portia.css):** the global reduce rule no longer exempts `.desktop-wallpaper`, and it still sets no `transition-duration`. A new rule `html[data-motion="reduce"] :is(.desktop-wallpaper, .desktop-wallpaper *) { animation: none !important; }` sets the drawn end states (web `stroke-dashoffset: 0`, dew `opacity: 1`). The web sway, dew twinkle, gel glow, cells drift and particle tumble rules are now scoped to `html[data-motion="full"]`.
- **Glints:** the `.wallpaper-web-pulses` group, its orbit paths, their rules and the `web-pulse` / `web-orbit` keyframes are deleted.
- **Helix:** `HELIX_LOOP = 720`, periods 240/180/360/144, and the columns are drawn from -120 over 1800 units. The grid svg uses viewBox `0 0 1440 1620`. Its height is `100% + 720 * max(100cqw/1440, 100cqh/900)`, and `helix-scroll` translates it by exactly that loop (linear, 90s, infinite). The per-column delays and `helix-drift` are gone. The built CSS keeps the container-unit expression (checked in `.next`).
- **Web:** `stroke-linecap: butt` on web paths. Spokes draw in 0.9s linear (delay index·30ms), rings in 1.2s ease-in-out (delay 450 + index·60ms). Dew fades in at 2.2s, the sway starts at 2.5s, and `web-sway` only rotates.
- **DOM:** the `.desktop-wallpaper-frame` (fixed, z-index 0, aria-hidden) holds `.wallpaper-layer` (absolute, overflow hidden, `container-type: size`), which holds the svg (now `position: absolute`). The svg moved into a `WallpaperArt` helper. The `DesktopWallpaper({ kind })` API is unchanged. The file is now marked `"use client"` because it uses hooks. Its only importer, portia-desktop.tsx, was already a client module.
- **Gel:** the bands and labels have no translate (`gel-run` deleted). The glow pass sits in `<g className="wallpaper-gel-glow">` at weight × 2.2 and breathes with `gel-glow` (12s, opacity .55 to 1, motion on only). Band weights are 3 + pick·3 and opacities 0.5 + pick·0.4, with the same seeded generators.
- **Crossfade:** `useState({ current, leaving })` is adjusted during render when `kind` changes. A `useEffect` drops `leaving` after `WALLPAPER_FADE_MS` (500) with `window.setTimeout`, and its cleanup clears the timer. Both layers render from one keyed list (`[leaving, current]`). The outgoing layer therefore reuses its DOM node and keeps its drawn state, instead of remounting and redrawing the web. `is-entering` is set only while a leaving layer exists, so the first render does not fade. CSS: 500ms fade-in/fade-out, and 300ms `!important` variants under «Выключены».

## Deviations from Plan

- **[Ordering] `WallpaperArt` was factored out in Task 2, not Task 3.** Task 2 already moved the svg into the layer, so the helper was introduced there and Task 3 only added the crossfade. Same end state.
- **[Rule 2 - Correctness] Single keyed list for the two layers.** The plan rendered the leaving layer and then the current one. They are rendered as one keyed array instead, so the outgoing wallpaper reuses its DOM node. Separate JSX slots would remount it, which restarts the web's draw animation in the middle of the fade.
- **[Rule 3 - Blocking] `"use client"` added to components/portia-wallpaper.tsx** because the component now uses `useState` / `useEffect`.

## Known limitations

- On page load, the desktop renders the default wallpaper («radar» = web) first and then applies the stored one in a `setTimeout(0)`. If the stored wallpaper is not the default, that swap crossfades for 500ms behind the opaque boot screen, which is shown for 1650ms on every load. The fade is not visible, but it does run. Skipping it would need a "restored" signal from portia-desktop.tsx, which this plan does not touch.
- When wallpapers are switched faster than 500ms, the oldest layer is dropped immediately: only one leaving layer is kept.
- No automated test for the crossfade state logic (it is a component without a DOM test harness). It is covered by the human check.
