Findings at planning time (re-grep; lines moved in waves 1-3):
- D-03. In components/portia-desktop.tsx, minimumWindowSize (~105) returns 680×320 for the editor and 440×320 for every
  other window. «Сотрудники» at 440 px: `.personnel-app` has grid columns minmax(260px, 32%) and minmax(0, 1fr), which
  leaves the profile about 180 px, so it squashes. The 03-06 container query
  `@container (max-width: 680px)` on .personnel-profile already stacks the profile head when the profile column is
  narrow. Above roughly 720 px of window width, list + stacked profile stay readable. `.archive-grid` uses
  minmax(270px, 24%) and 1fr; its `.record-hero` uses minmax(240px, .86fr) and minmax(320px, 1.14fr), which needs 560 px
  plus a gap and overflows a narrow record view. That is handled by D-08's container stacking below. The preferred
  opening sizes live in createWindowGeometry (~80-91). fitGeometry already lets the minimum give way on a smaller screen.
  minimumWindowSize is called from createWindowGeometry, the open path, the viewport refit and AppWindow's moveResize.
- D-08. VirusRecord (~1526-1534) builds the classification cells in the order danger, spread, transmission, escapeRisk,
  mind, appearance, behavior. The CSS grid (~774) has 2 columns with `.class-cell.transmission { grid-column: 1 / -1 }`,
  so escapeRisk («Угроза и риск побега») lands below «Способ распространения». The 900px block sets 2 columns (~962);
  the 430px block sets 1 column and drops the full-row span (~1110-1111). In the cell, `<strong>` holds the badge svg
  (`.class-badge` 18px, vertical-align −3px, margin-right 6px) inline with 15px bold text. The cell is a column flex
  with justify-content: space-between, so icon and name don't share a centre line. The owner calls one of the threat
  items «Угроза распространения». Putting danger, spread and escapeRisk all above transmission satisfies it whichever
  label he means. Labels stay as they are; the human-check asks him.
- The 03-06 pattern for stacking by window width rather than viewport: `container-type: inline-size` on the column plus
  an `@container (max-width: …)` block.
