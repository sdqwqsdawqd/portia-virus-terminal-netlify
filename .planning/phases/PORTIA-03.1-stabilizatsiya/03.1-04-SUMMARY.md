# Phase 03.1 Plan 04: Boot once per session, spider on its thread, one font for Vivian Summary

The boot screen now plays once per browser tab session. The constant head script reads a sessionStorage key before first paint and sets `html[data-boot="seen"]`, and CSS hides the boot screen for that session, so a reload paints the desktop with no boot flash. A new tab or a new session plays it again, and if storage is blocked it plays every time. The thread now runs the spider's own `spider-descend` animation, so the spider hangs on its thread from the first visible frame. Every Vivian phrase (tip, idle, activity, offended, after the sulk) is pinned to the tips' type, measured in a real browser. The offended and recovering states change only colours.

## Task 2 step 1: what was found

**(a) Static cascade.** The text root (`span.formatted-content.assistant-formatted-text`, a direct child of `.assistant-bubble`) was matched by the heading rule `.assistant-bubble > span` (0,1,1). That rule beat `.assistant-formatted-text { font: 700 10px/1.5 … }` (0,1,0) at every width, including the ≤900px 9px rule and the ≤520px 10px/1.45 rule. So the root rendered `500 11px var(--sans)` (IBM Plex Mono), letter-spacing .09em (0.99px) and line-height normal. All text sits in run spans, and `.assistant-formatted-text > span` pinned them to `700 10px var(--assistant-font)` with `!important`. They inherited the 0.99px letter-spacing and line-height normal, and the root's Plex Mono 11px strut set the line pitch. No offended, recovering, data-auto or data-mood rule sets typography. This held for each state at desktop, ≤900px and ≤520px.

**(b) Content** (read-only GET of http://localhost:3123/api/content, revision updatedAt 2026-10-16T08:16:44Z):
- `assistant:advice`: 1 run, no style, 4401 chars, 1 GIF link (klipy anime-tsundere-6).
- `assistant:offended`: 1 run with the inline style `{ color: #aebfba, fontSize: 17, fontWeight: 400, backgroundColor: #f0d66a, backgroundOpacity: 0 }` over all 601 chars, no GIF links. 14 offended phrases.
- `assistant:idle`: 1 run, no style ("Ау! Кто-то здесь есть???"). `assistant:activity`: 1 run, no style (activity phrases are off).

**(c) Measured in a real engine** (headless Edge over CDP, against the dev server's real CSS, animations frozen). A probe bubble per state used the offended run's real inline style. Before the fix, the tip, offended and recovering runs all computed to `"Segoe UI" 10px 700, letter-spacing 0.99px, line-height normal`, with a 14px line pitch and the same box heights (70 / 70 / 58 px at 1280 / 760 / 400 px wide). Only the colour differed (#ffd98c on offended). After the fix, root and runs compute to `"Segoe UI" 10px 700, 0.99px, 14px` with the same pitch and heights, so tips are pixel-identical to before.

**Conclusion: what actually makes the offended phrases look different.** In the current code, nothing on the desktop does: the offended phrases already render in the tips' font and size, and only the warm colour differs. The only real typographic difference is in the content. The owner's offended text carries a stored run style of 17px, weight 400, grey #aebfba. The `!important` pin (present since 5001944, 2026-10-11) hides it on the desktop, but the editor's rich input shows it (there the offended phrases look 17px regular and the tips 10px bold). An older deployed build or a warm colour that reads as a different weight are other possible sources of the report. The fix pins every phrase element (root and all descendants) to one style at the tips' measured values. That holds whatever runs the editor stores, and it removes the accidental heading-on-root cascade. The stored 17px style was not changed: the plan forbids writes to the live API. The owner can clear it with the editor's formatting controls if the editor view bothers them.

## Deviations from Plan

**1. [Rule 1 - Bug] Line-height pinned to the measured 1.4, not "normal"**
- **Found during:** Task 2 step 1
- **Issue:** The plan expected the tips' line-height to be "normal". The computed value is "normal", but the line pitch comes from the root's Plex Mono 11px strut (14px). Moving the root to Segoe UI 10px with line-height normal would have tightened every phrase's line spacing.
- **Fix:** `line-height: 1.4` (14px at 10px), checked pixel-identical in Edge. Letter-spacing is `.099em`, the inherited 0.99px expressed at 10px.
- **Files modified:** app/portia.css. **Commit:** 321ac1b

**2. [Rule 1 - Bug] Breakpoint and root typography removed instead of kept**
- **Found during:** Task 2
- **Issue:** Once the heading rule stopped matching the root, the ≤520px `line-height: 1.45` and the ≤900px 9px would have started to apply where they had been dead, changing the phone look.
- **Fix:** Removed them and the duplicate ≤520px run rule, so the single pinned rule is the only source of typography (the breakpoints no longer set a size at all; they would be equal anyway).
- **Files modified:** app/portia.css. **Commit:** 321ac1b

**3. Confirm step went further than planned.** Besides the static audit and the content GET, the cascade was measured in headless Edge, because static reading alone could not settle where the owner's difference came from. Probe files live only in the session scratchpad and a temp Edge profile, and nothing was written to the repo or the API.

The planned cause was only partly right. The heading rule on the root was real but affected all phrase kinds equally, and no offended-only font rule exists. The real typographic difference is the stored 17px/400 style on the offended content (see step 1).
