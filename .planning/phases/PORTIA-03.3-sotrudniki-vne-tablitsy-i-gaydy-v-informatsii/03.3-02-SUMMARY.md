# Phase 03.3 Plan 02: Guide subsections, text blocks and classification tables Summary

**A «Информация» category now holds up to 50 ordered subsections made of text and «признак — значение» table blocks in any order, edited and reordered in the editor, opened from a tree on the desktop and found by global search; pre-03.3 flat sections normalize to `subsections: []` unchanged.**

## Accomplishments

- `lib/portia-content.ts`: `InfoBlock` (text, table, photo, video), `InfoSubsection`, `InfoSection.subsections`, `findInfo(sections, id)`; the four default sections carry `subsections: []`.
- `lib/portia-content-normalize.ts`: `normalizeInfoSections` (allow-listed block types, caps 50/100/100, lengths 300/20000/500, photo url via `normalizeMediaUrl`, videoId only `/^[\w-]{11}$/`, id fallbacks as in the plan). `normalizePortiaContent` no longer passes `infoSections` through. Section title and body are type-checked, never cut.
- `components/portia-desktop.tsx`: fetched and cached copies pass through `normalizeInfoSections`; the selection, both refetch resets and search opening resolve through `findInfo`; tree with `aria-expanded` and `.info-subsections`; subsection pane (eyebrow with the category, h1, `.info-blocks`); text block as `FormattedText`; table block as `dl.info-ledger.info-classification` (empty rows skipped); one search hit per subsection (`ИНФОРМАЦИЯ · <раздел>`), category hits unchanged.
- `components/portia-editor.tsx`: «+ ПОДРАЗДЕЛ», «+ ТЕКСТ», «+ ТАБЛИЦА», «+ СТРОКА», «Удалить строку»; subsection and block cards with `OrderDragHandle` (`moveArrayItem` on the section / subsection found by id); `OrderDragHandle.moveTo` restricted to sibling rows; guidance text updated.
- `app/portia.css`: tree indentation with thin rule, block rhythm, `dt`/`dd` ledger rules, editor list and table-row layout, phone layout (tree stays a horizontal strip, table rows stack). No colour literal beyond one already used in the file.
