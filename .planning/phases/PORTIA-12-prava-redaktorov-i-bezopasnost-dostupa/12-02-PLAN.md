<objective>
Write the pure rules that decide what a closed tab means for content. They answer three questions: which closed sections does a save change, how do we put closed sections back to the stored copy, and how do we keep undo from bringing those edits back.

Purpose: PERM-04's server check (12-05) and PERM-03's editor behaviour (12-06) both rest on these functions. Here they can be tested without a browser or a database. RESEARCH found a gap in the current section map (`info-block:`) that would let a closed «Информация» be edited.

Output: new functions in `lib/editor-changes.ts` and one new history action, all with tests.
</objective>

Facts checked at planning time:
- `lib/editor-changes.ts`: `prefixSections` lists "info:", "broadcast:", "recycle:", "search:", "assistant:". `portiaTextKey.infoBlock` (lib/portia-content.ts:182) builds `info-block:<id>:text`, which maps to no section. `sectionOfFormattedKey` puts `virus:<id>:*` keys under viruses when the id is in either copy's `viruses`, otherwise under recycle.
- Every top-level key of the normalized content except `formattedText` maps to a section. A probe this session confirmed it, and the existing test "every content key except formattedText belongs to a section" also covers it. So only formatting keys can be unclassified.
- `normalizePortiaContent(normalizePortiaContent(defaultPortiaContent))` equals `normalizePortiaContent(defaultPortiaContent)` (probe this session), while `defaultPortiaContent` itself is not in normalized form.
- The editor's move to the bin (components/portia-editor.tsx:798-811) pushes the virus record into `recycledViruses`, removes it from `viruses` and rebuilds `recycleOrder` with `recycleKeys`. That uses the same rule as the normalizer's recycleOrder (lib/portia-content-normalize.ts:273-280), so on normalized content the order changes only by the moved `virus:<id>` key.
- Restore (portia-editor.tsx:1434-1444) moves a bin virus back to `viruses`. D-13: that needs «Корзина» open.
- `lib/editor-history.ts` `historyReducer` never mutates entries. `HistoryAction` has change/discard/undo/redo/saved/sync. The existing test "undoing every step returns the baseline object itself" relies on entry identity.
- Fixture style: `const fixture = (): PortiaContent => structuredClone(defaultPortiaContent);` in lib/editor-changes.test.ts.
