### EDIT-02 — target mark contrast (researcher decision, computed)
- Replace `::highlight(portia-format) { text-decoration: underline solid rgba(var(--desktop-glow), .9) 3px }` with **`text-decoration: underline solid rgba(0, 150, 132, .95) 3px`**. Teal hue is kept, still no fill [Phase 5 rule, CTX D-17].
- Measured contrast (WCAG relative luminance): on light field `#f3f1e9` **3.26:1** (was 2.12:1; passes 1.4.11 >= 3:1); on dark field `~#101c1a` **4.73:1** (was 7.27:1; still clearly visible). Paper `#f3f0e6` / `#f5f3eb` variants differ by < 0.1.
- `::highlight` cannot read CSS custom properties from the field, so one shared colour is used (no second highlight name). Test (TEST-02) asserts: rule exists, has `text-decoration: underline`, contains no `background`/`background-color`, and the colour is the value above.

## Layout & Interaction Contracts

### 1. Section navigation — EDIT-03 [CTX D-01..D-05]
- On editor entry every section/subsection (Информация sections+subsections, virus cards, summary, trash, and all other lists using `OrderDragHandle`) renders **collapsed**: only the header row (handle `≡`, title, collapse toggle, existing row actions). State is held in component state only; never persisted.
- Header row layout: `[≡ handle] [title (flex 1, min-width 0)] [toggle] [row actions]`. Title: `overflow: hidden; white-space: nowrap; text-overflow: ellipsis; min-width: 0`, with `title` attribute = full text. Row actions never overlap — this fixes the existing bug where a long title spills over the neighbour's buttons.
- Toggle: button `▸` collapsed / `▾` expanded, `aria-expanded`, `aria-controls` the body id. Whole title is also clickable to toggle (not the handle).
- TOC: a compact `ОГЛАВЛЕНИЕ` block pinned at the top of each long list (sticky inside the list, `top: 0`, 11px/700 items, 8px gap, `max-height: 40svh`, scrolls). Each item is a button: click expands that section and `scrollIntoView({ block: "start", behavior: smooth })` — use `behavior: auto` when `prefers-reduced-motion: reduce`. Rendered only when the list has >= 5 items [DEFAULT]. No search field [CTX D-03].
- Reorder: handle `≡` drags collapsed rows within one screen; no up/down buttons [CTX D-04]. A section being dragged is force-collapsed for the drag duration.
- Expanded sections keep current inner layout unchanged.

### 2. Floating format panel — EDIT-04, EDIT-01 [CTX D-06..D-08]
Desktop (> 900px):
- Rendered through a React portal into the desktop layer in `portia-desktop.tsx`, `position: fixed`, `z-index: 130` (existing value; above windows, below modal `ConfirmDialog`/toasts). Not a PORTIA OS window: no taskbar entry, no minimise.
- Width `min(680px, calc(100vw - 28px))`, max-height `min(48svh, 390px)` [CODE]. Drag by `header` (cursor `grab` / `grabbing`, `touch-action: none`, `user-select: none`) anywhere on the whole screen; clamp so >= 64px of the header stays inside the viewport on all sides (extend `clampPanelOffset`).
- Header buttons (×) remain clickable and are excluded from drag start.
- Initial position (no stored value): right of the editor window with 16px gap if it fits; otherwise bottom-right of viewport with 16px inset. Stored position (`portia-format-panel-v1`) is now relative to the desktop/viewport; legacy editor-relative values are reinterpreted via clamp, never throw. Storage read/write inside try/catch.
- Closes with the editor window (unmount). Panel survives editor window being moved/resized/focused.
- Keyboard: `Esc` in panel returns focus to last text field (does not close panel). Header is focusable (`tabindex=0`); arrow keys move panel 8px (Shift = 32px) [DEFAULT, a11y alternative to drag].

Phone (<= 900px):
- Bottom sheet: `position: fixed; left: 0; right: 0; bottom: 44px` (above bottom nav), `max-height: min(34svh, 270px)` [CODE], no free drag, no stored offset.
- One tap on the header strip (or the `▾` toggle, 44px target) collapses to a **44px strip** showing `ОФОРМЛЕНИЕ` + `▴`; tap again expands. State is per-session, default expanded when opened.
- EDIT-01: tapping ГОТОВО with no known selection must NOT place the caret at offset 0; the next ✎ opens with `ВЫДЕЛИТЕ ТЕКСТ`, no word targeted.

### 3. Save chip — EDIT-05 [CTX D-09..D-11]
- Replaces the full-width `.editor-savebar` strip. A chip anchored `position: absolute; right: 12px; bottom: 12px` inside the editor window (sticky within scroll area). Size: min 32x32 desktop, 44x44 phone; border-radius 4px; shows the number of changed sections (11px/700). Border + count colour: `--warning` when dirty; `--danger` when save is blocked (limit / bad quest date); neutral when clean — in clean state with nothing to show the chip is not rendered.
- Click/Enter toggles a popover (anchored above the chip, width `min(320px, calc(100% - 24px))`, max-height 60svh, same surface as floating panel): title `НЕ СОХРАНЕНО`, list of changed section labels, status/blocked reason text, and the three existing actions `↶`, `ОТМЕНИТЬ`, `СОХРАНИТЬ`. `Esc` or outside click closes; focus returns to chip.
- `role="status" aria-live="polite"` stays on a visually available node so screen readers still announce changes; chip has `aria-expanded`, `aria-haspopup="dialog"`.
- Phone: chip sits above the sheet — `bottom: calc(44px + {sheet height or 44px strip} + 8px)`; when panel is not open `bottom: 52px`. Chip never overlaps the sheet or bottom nav. Remove the `:has(.floating-text-format)` padding hacks (`portia.css:500,509,644,1187`) that reserved space for the old strip.
- Keyboard shortcut Ctrl/Cmd+S (Phase 10 D-21) keeps working and triggers `СОХРАНИТЬ`.

### 4. Multi-selection — EDIT-06 [CTX D-12..D-17]
- Desktop only (feature disabled when `(max-width: 900px)` or `pointer: coarse`).
- Ctrl (Cmd on Mac) + selecting text adds a fragment; fragments may live in different fields. Plain click/selection without Ctrl, or Esc, clears all fragments. Ctrl+click on an already-selected fragment removes only it.
- Overlapping and adjacent fragments merge into one; style is applied once per merged range.
- Each fragment is painted through the single `CSS.highlights` entry `portia-format` (one `Highlight` with N ranges) — same teal underline, no fill [CTX D-17].
- Panel header shows `ВЫБРАНО: {N}` (accent value) plus a `СБРОСИТЬ` button when N >= 2 (min-height 32px, secondary-button style from `.floating-text-format > footer button`). With N = 1 the existing `СЛОВО`/`{N} ЗНАК.` label stays.
- Applying a style to all fragments is one history step in `lib/editor-history.ts`; Ctrl+Z reverts every field at once, one `↶` press also.
- Selection can be lost when focus moves into panel inputs; fragments are stored as (field key, start, end) and restored on apply.

### 5. Tables — EDIT-07 [CTX D-18, D-19]
- Each row gets a leading `≡` (`OrderDragHandle`, reusing `moveArrayItem` + `editTableRows`); 34px desktop / 44px phone. Row grid: `[≡] [Признак input] [Значение input] [удалить ×]`; inputs `min-width: 0`.
- Column headers `Признак` and `Значение` each get a `≡` handle (same visual, `aria-label` per table above). Dragging one over the other swaps the two columns across all rows; order persists in content and renders on the public site (`dl`: `dt` = first column, `dd` = second) — storage approach is planner's choice (swap `key`/`value` or store an order flag).
- Drag feedback reuses existing `[data-dragging="true"]` styles (teal border, `--teal-soft`, lifted row). While a column header is dragged, a 2px `--teal` drop indicator marks the target header.
- Keyboard reorder for handles follows the existing `OrderDragHandle` behaviour (no change).
