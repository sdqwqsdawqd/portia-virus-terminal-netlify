<objective>
Close the one verification gap of Phase 11. The multi-field format target (`peers` and `fragments`, built in 11-06) must stay in step with the draft. This plan closes review findings CR-01, WR-01 and WR-02 and the archived-virus mutation delete path. It adds a unit test and a harness check, so the 11-06 safety prohibition is enforced by tests.

Purpose: today a style click can write formatting for a deleted item (an orphan in `formattedText` that gets saved), style shifted ranges after a Ctrl edit, or style text inside a folded card. The prohibition «never styles characters outside the fragments or fields that hold none» was marked test-verified, but no test touched these paths.

Output:
- `dropFields` in `lib/format-fragments.ts` with 3 tests;
- `dropFormatFields` in the editor, used by `closeFormatterFor`, `toggleCard` and `setAllOpen`;
- the section delete names its block keys;
- `commitEditorValue` ends the gesture;
- the archived `onRemoveMutation` clears the target;
- harness check `peers` (a)-(d);
- the disposition ledger updated.

Planner decisions:
1. One pure helper, one editor wrapper. `dropFields(target, gone)` (generic, no imports, unit-tested) does the pruning. `dropFormatFields(gone)` in PortiaEditor does two things. It closes the panel when the main target's key is gone, reading the `formatTarget` closure as the existing code does. It applies `setFormatTarget((prev) => prev && dropFields(prev, gone))` as a functional updater. The functional updater keeps the existing `subsection.blocks.forEach(... closeFormatterFor ...)` loop correct: each call chains on the previous one.
2. WR-01 is fixed at the one funnel every text change passes through. This is the review's alternative fix, «clear fragments and peers whenever the field's own onChange fires». `commitEditorValue` (called by Enter, onPaste and onInput) starts a plain gesture first, so it covers every case: Ctrl+X/V/Backspace/Delete, Ctrl+Enter, context-menu cut/paste and drop, in any keyboard layout. A key list would miss some of these. On a Russian layout, `event.key` for Ctrl+V is «м». This also closes CR-01's stale `peer.value` snapshot: a peer field can only change text by being edited, and that edit now clears the peers.
3. The archived-virus mutation delete (`onRemoveMutation`, ~1431) gets the same `setFormatTarget(null); setFormatterOpen(false);` as the live mutation delete (~1231). The live delete keys formatting by position, which a delete shifts. Note: `ArchivedVirusEditor` renders the mutation «Описание» as a plain `<textarea>`, so no harness step can hold a format target on an archived mutation. The change is defensive and checked by source grep only.
4. Out of scope, because they are not in the VERIFICATION `gaps:`: WR-03 (panel remount on key change), IN-01 and IN-02. A stale target on an unmounted recycle-file field after a record switch is also out of scope. All of these stay `open`.
</objective>
