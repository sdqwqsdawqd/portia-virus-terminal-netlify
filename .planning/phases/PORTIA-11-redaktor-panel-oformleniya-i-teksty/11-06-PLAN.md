<objective>
Let the owner select several text fragments with Ctrl, even in different fields, and style all of them with one click (EDIT-06; owner decisions D-12 to D-17).

Purpose: colouring the same word in ten places takes ten round trips through the panel today. The owner asked for Word-style multi-selection on a PC.

Output:
- `lib/format-fragments.ts` with tests;
- a `batch:` history key;
- gesture-tagged format targets carrying fragments and the peer fields;
- one apply path for every panel control;
- the «ВЫБРАНО: N» / «СБРОСИТЬ» header and N-range highlighting;
- harness check `multiselect`.

Planner decisions:
1. Multi-selection state lives inside `FormatTarget` (`fragments`, `peers`, `gesture`). Every existing `setFormatTarget(null)` path therefore clears it by construction: undo, discard, tab switches, deletes, collapsing a card. A new FormattedTextarea gesture decides the rest. A non-modifier pointerdown or keydown (typing shifts offsets) starts a plain gesture, which clears it. A modifier pointerdown starts an additive one, which keeps the fragments and adds the previous selection.
2. The first fragment is the previous non-collapsed selection. A bare caret is not a fragment: the word-under-caret rule applies to single selection only.
3. Undo grouping: a multi apply runs under `batch:<id>` keys. The reducer folds them regardless of time, as it does `drag:`. A fresh id per control interaction keeps two different clicks as two steps. The id is reused while the same control keeps firing with no 700 ms pause (`TYPING_PAUSE_MS`), so a slider or colour-board drag is one step.
4. Single-selection behaviour, its undo coalescing and every existing test stay unchanged.
</objective>
