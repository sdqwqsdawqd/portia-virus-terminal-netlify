# Как изменять PORTIA перед публикацией

## Где находится проект

GitHub: `https://github.com/sdqwqsdawqd/portia-virus-terminal-netlify`. Сайт публикуется в Netlify автоматически из ветки `main`.

## Самый простой способ

Напишите в этом чате, что именно нужно изменить. Например:

- «Добавь приложение с картой лаборатории»;
- «Измени цвет рабочего стола»;
- «Передвинь Корзину вниз»;
- «Добавь новое поле в карточку вируса»;
- «Исправь отображение на телефоне».

Я внесу изменения в код, проверю сборку и покажу результат. Изменения попадают на сайт только после слияния Pull Request в `main` — по вашей отдельной команде.

## Основные файлы

| Что меняется | Файл |
| --- | --- |
| Рабочий стол, окна и приложения | `components/portia-desktop.tsx` |
| Встроенный редактор содержимого | `components/portia-editor.tsx` |
| Цвета, размеры, телефонная версия | `app/portia.css` |
| Начальные вирусы и тексты | `lib/portia-content.ts` |

| Проверка сохраняемых данных | `lib/portia-content-normalize.ts` |

| Правила доступа в базе | `supabase/portia_setup.sql` |

## Как запустить сайт на компьютере

Откройте терминал в папке проекта и выполните:

```powershell
npm.cmd run dev
```

Затем откройте `http://localhost:3000`.

Изменения интерфейса будут появляться после сохранения файла. Чтобы остановить сервер, нажмите `Ctrl+C`.

## Как проверить сайт перед публикацией

```powershell
npm.cmd run check
```

Команда запускает тесты, проверяет сборку и ошибки кода. Предупреждения об обычных тегах изображений не мешают публикации.

## Как устроено редактирование содержимого

После первой публикации тексты и вирусы лучше менять через встроенный редактор:

1. Откройте **Настройки**.
2. Нажмите **Войти в редактор**.
3. Введите email и пароль пользователя Supabase.
4. Снова откройте **Настройки → Открыть редактор**.
5. Измените данные и нажмите **Сохранить всё**.

В редакторе можно изменять вирусы, информационные разделы, объявления, подсказки поиска, советы помощника и файлы Корзины. В Корзину можно добавлять связанное досье вируса, обычный текстовый документ или фотографию.

Такие изменения сразу записываются в Supabase и становятся видны всем посетителям. Код сайта менять не требуется. Посетители могут только читать файлы Корзины — менять и удалять их может только владелец через редактор.

### Как добавить редактора

Главный владелец открывает **Редактор → Доступ**, указывает email человека и выдаёт доступ. Затем этот человек на странице `/owner-login` создаёт свой аккаунт с тем же email и собственным паролем. Владелец может в любой момент отозвать права, не удаляя содержимое сайта.

Перед первым использованием этой функции снова выполните `supabase/portia_setup.sql` в Supabase SQL Editor. SQL-файл можно выполнять повторно: он создаст таблицы и обновит правила. Email владельца задаётся только в функции `portia_owner_email()` этого файла.

Если два редактора правят сайт одновременно, сохранится только первое сохранение. Второй увидит сообщение «Кто-то сохранил раньше»: скопируйте свои правки, обновите страницу и внесите их заново.

### Профили сотрудников

Состав, позывные, звания и ранги берутся из Google-таблицы (34 строки сотрудников) и обновляются раз в час. Биографию, фото и оценку знаний меняют в **Редактор → Сотрудники**; они хранятся в Supabase и не затираются синхронизацией. Профиль привязан к аккаунту Roblox, поэтому смена ника в таблице его не теряет.

### Классификация и записи учёных

Классификация выбирается из готовых вариантов. Уровни 1, 2 и 3 отмечены зелёным, жёлтым и красным только внутри редактора; в публичном досье все значения отображаются нейтральным цветом.

Для каждого вируса можно оставить от 0 до 5 записей учёных. Запись с уровнем **II** доступна посетителям, а записи уровней **III** и **IV** показываются как заблокированные. Большое текстовое поле работает по принципу «что видите, то и получите»: текст редактируется сразу с выбранным цветом, размером, толщиной и фоном, поэтому отдельного предпросмотра нет. Сначала нажмите в нужное поле и при необходимости выделите фрагмент, затем используйте единственную кнопку **Оформление** над формой. Если выделения нет, меняется всё активное поле. В панели есть готовые палитры, встроенный выбор собственного цвета, вариант **Без фона**, настройка плотности фона и переключатель белого/чёрного фона предпросмотра. Тёмный предпросмотр автоматически включается для разделов, которые посетители видят на тёмном фоне. На телефоне используется та же компактная панель.

Код нужен для изменения дизайна, структуры окон, функций и новых типов полей.

## Изображения вирусов

В редакторе изображения заражённых, мутаций и фотографии Корзины можно выбрать с компьютера или перетащить в область загрузки. Также можно вставить готовую публичную ссылку. Не вставляйте локальные пути вида `C:\...` — посетители сайта их не увидят.

Фотографии для Корзины можно загружать прямо с компьютера. Перед первой загрузкой откройте в Supabase раздел **SQL Editor** и ещё раз выполните весь файл `supabase/portia_setup.sql`. Он создаст закрытый для записи контейнер `portia-media`; загружать туда смогут только владелец и выданные им редакторы.

Советы, обиженные фразы и варианты времени терпения меняются в разделе **Редактор → Помощник**. Каждая фраза вводится с новой строки, а варианты времени — числами через запятую. Советы и обиженные ответы показываются в случайном порядке без повторов, пока не будет использован весь соответствующий список. Если между быстрыми нажатиями проходит больше примерно одной секунды, отсчёт терпения начинается заново.

Жёлтый кружок на ярлыке **Сводка** означает, что после последнего просмотра появилось новое или изменённое опубликованное сообщение. После открытия «Сводки» кружок исчезает. Отметка о прочтении хранится отдельно в браузере каждого устройства.

## Предварительная версия

Когда изменения готовы и проверены, они отправляются в GitHub отдельной веткой с Pull Request. Netlify собирает для него временную ссылку для проверки, основной сайт при этом не меняется. Учтите: предварительная версия работает с той же базой Supabase, поэтому сохранения в её редакторе видны на основном сайте.

## Финальная публикация

Только после окончательной проверки Pull Request сливается в `main`, и Netlify публикует сайт автоматически.

## Что нельзя публиковать

- `.env.local`;
- пароль владельца;
- Supabase `service_role` key;
- любые личные документы или секретные ключи.

Файл `.env.local` уже исключён из Git.
